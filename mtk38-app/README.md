# МТК 38 · «Ленин на языках народов мира» — киоск-приложение

Пять прежних прототипов собраны в одну страницу на общем ядре
(`assets/shared/kiosk/kiosk-core.esm.js`, версия 1.7.0). Открывать **только по
http** — ES-модули из `file://` не грузятся:

```bash
python3 -m http.server 8092
```

затем `http://localhost:8092/mtk38-app/` (сервер на 8092 держит координатор;
у сессии МТК 38 свой порт 8093).

## Сцены

| № | Сцена | Откуда | Движок | Что показывает |
|---|---|---|---|---|
| 1 | **Глобус** (по умолчанию) | v3 `globe.html` | WebGPU + TSL | 60 написаний кольцами по параллелям вокруг Земли |
| 2 | **Дождь имён** | v3 `rain.html` | WebGPU-compute, фоллбэк Canvas 2D | написания всплывают снизу вверх, палец расталкивает |
| 3 | **Карта** | v3 `map.html` | Canvas 2D | Winkel Tripel: языки, города печати, связи с Москвой |
| 4 | **Каталог** | v1 `mtk38-catalog` | Canvas 2D | сетка 128 языков, листается, фильтры все/ООН/с изданием |
| 5 | **Композиции** | v2 `studio` | WebGPU | облако · мандала · лента · стена + слой цитат |

Плакат (`mtk38-poster`) в приложение **не вошёл**: он тянет `pretext` с
`esm.sh`, а музейный киоск может стоять офлайн. Вернётся, когда зависимость
будет вендорена.

Тап по написанию в любой сцене открывает одну и ту же карточку языка
(`scenes/card.js`): написание, языки этой формы, ареал, носители, письменность,
семья, метка выверенности и издание на этом языке с обложкой.

## Устройство

- `app.js` — регистрация сцен и аттрактор-чередование для standby.
- `scenes/shared.js` — единая загрузка канона и изданий, палитра, шрифтовые
  стеки, кап буфера. Данные грузятся **один раз** на всё приложение.
- `scenes/gpu.js` — **один** WebGPU-рендерер и **один** канвас на три
  GPU-сцены. Сцены забирают канвас в `resume()` и снимают свои слушатели в
  `pause()`. Так сделано потому, что ядро держит сцены смонтированными
  (`keepAlive`), а девайс на каждый показ — утечка контекстов за смену.
- `scenes/card.js` — карточка языка (единая для всех сцен).
- Настройки объявлены схемой в самих сценах (`settings[]` + `applySettings`);
  ядро исполняет схему само — моста из эталона 42 здесь нет.
- Версии в адресах обязательны: `?v=` у модулей и CSS, `i18nVersion` у словарей,
  `?v=` у самой обёртки ядра (она передаёт версию дальше в `kiosk-core.js`).
  Без последнего Chrome отдавал ядро из кеша — приложение работало на 1.5.0,
  когда в репозитории уже лежало 1.7.0.

Всего **65** объектов настроек: Композиции 20 (из них 6 — цитаты), Глобус 15,
Дождь 13, Карта 10, Каталог 7. Значения живут в
`localStorage["mtk38-kiosk"].scenes.<id>`.

Перенесены все позиции класса А из `SETTINGS-INVENTORY.md`, включая те, что
достались от прототипов без собственной сцены: «Радиус bloom» и «Плотность ×»
(бывший `mtk38-cloud`) — в Композиции, «Сетка» — в Карту. Снятых позиций нет.

## Standby

Сцены следуют контракту ядра: `standby()` без аргумента возвращает
стоп-функцию своей петли. Саму петлю ведёт ядро — `app.standbyTicker(draw)`,
`timings.standbyFps` (10 к/с); в `scenes/shared.js` к ней добавлена только
защита от наложения асинхронных кадров WebGPU. Зритель издалека видит саму
сцену, а не оверлей ядра, и GPU ночью не работает на полных кадрах. Ротация (`standby.mode: "rotate"`) живёт в `app.js` поверх
этого: гасит петлю уходящей сцены, показывает следующую и сразу переводит её в
заставочный режим. Стоп-функция у всех сцен — одна ссылка (`scenes/shared.js`),
поэтому ядру неважно, какая сцена окажется активной к приходу посетителя.

Известное поведение: глобус, дождь и композиции делят один канвас, поэтому на
время кроссфейда (350 мс) между двумя GPU-сценами кадр темнеет. На активной
работе это читается как переход; в заставке смена идёт раз в 25 с.

## Зависимости

Всё локально, рантайм-обращений в сеть нет
(`python3 assets/shared/kiosk/tools/audit-offline.py --path mtk38-app`).

Приложение опирается на файлы соседних прототипов — при их удалении нужно
перенести вместе с приложением:

- `mtk38-v3/vendor/three/` — Three r184 (импорт-карта в `index.html`);
- `mtk38-v3/fonts/faces.css` + `fonts/*` — бренд и 32 письменности Noto;
- `mtk38-v3/engine/{renderer,atlas,text}.js`, `mtk38-v3/scenes/{globe-rings,earth,rain}.js`;
- `mtk38-v3/geo/countries.geojson`;
- `mtk38-v2/shared/quotes.js` + `quotes.css` — слой цитат.

## Приёмка

```bash
python3 assets/shared/kiosk/tools/audit-offline.py --path mtk38-app
```

Стенд киоска — из консоли **видимой** вкладки (`?service=1`):

```js
await KioskSelfTest.run(mtk38App)
```

Последний прогон (12 циклов, 60 переходов): 8 из 10 зелёных — DOM 846→846, heap
+0.3 МБ, слоёв ровно по числу сцен, после старта сеть молчит (всё тяжёлое ушло
в `preload`), буфер в бюджете 8.3 Мп, тач-цели ≥ 64 px, скролл размечен
`kiosk-scroll`. Проверки «0 rAF у неактивных сцен» и «отступ от кромки» в
фоновой вкладке недостоверны (там `innerWidth = 0`, и «у кромки» оказываются
даже стрелки самого ядра) — стенд предупреждает об этом сам.

Заставку тоже проверяют на видимом экране: в фоновой вкладке браузер душит
таймеры до одного срабатывания в секунду и не обновляет композитор. На видимом
экране замер даёт 8 кадров за секунду при минимальном интервале 98 мс — ровно
`standbyFps: 10`; глобус в заставке виден, поверх только призыв коснуться.

Ссылки внутри зоны МТК 38 проверяются отдельно:

```bash
python3 assets/shared/kiosk/tools/audit-links.py --path mtk38-app
```

(и так же для `mtk38-v2`, `mtk38-v3` и прочих `mtk38-*` — сейчас везде ноль).
