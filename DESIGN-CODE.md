# BMK Design Code — эталон дизайн-системы музейного киоска

**Что это.** Переносимый дизайн-код, извлечённый из проекта **BMK 38-42** (пять мультимедийных комплексов музея В.И. Ленина, Ленинский мемориал). Служит **эталоном для всех проектов того же заказчика** — берётся целиком или по разделам, применяется у себя. Не про конкретные МТК: здесь только принципы, токены и приёмы, которые переносятся.

**Среда, под которую всё сформулировано** (она диктует правила — не вкус):
- **Музейный киоск**, дисплей **49″, 3840×2160**, целевая ориентация **вертикаль 2160×3840** (поворот дисплея; уточняется у куратора для конкретного зала).
- **Тач**: палец ≈ 15 мм ≈ 53 px, посетитель любого возраста.
- **Офлайн**: киоск может стоять без сети. **Любая рантайм-зависимость от сети = чёрный экран.**
- **Автономность**: приложение крутится сутками без оператора.

Каждое правило ниже — следствие этой среды. Отклоняешься от среды — правило можно пересмотреть; в этой среде — нет.

## 1. Палитра

Брендбук в CSS-токенах. **Единственный источник цвета — токен.** Сырой hex в компонентах запрещён (ловится линтером).

```css
:root {
  --amber-black: #000000;  /* чёрный янтарь */
  --white:       #FFFFFF;
  --brass:       #D2B773;  /* латунь (песочно-жёлтый) — активное состояние, акцент */
  --red:         #A02128;  /* сигнальный красный — ТОЧЕЧНЫЙ акцент, НЕ заливка */
  --blue-grey:   #5D8970;  /* сине-серый */
  --window:      #9DA3A8;  /* серое окно */
  --graphite:    #435059;  /* графитовый — БАЗОВЫЙ ФОН */
  --telegrey:    #CFD0CF;  /* телосерый */
  --paper:       #F7F9EF;  /* тёплый белый — текст на тёмном */
}
```

**Правило дизайнера (императив):**
- **Фоны — в оттенках СЕРОГО** (graphite/window/telegrey). Не тёплые, не красные.
- **Красный — ТОЧЕЧНО, не заливкой.** Крупные красные пятна убрать. Красный — сигнал (статус, критический акцент), не поверхность.
- **Без диагональных полос по фону.** Декоративные диагонали убрать; полосы — только функциональная кромка.
- **Активное состояние — латунь, не красный.** Выбранный чип/таб/кнопка = латунь. (Дешёвая первая правка при миграции чужого стиля: перекрасить активную заливку с красного на латунь.)

**Приём — RGB-канальные токены.** Для полупрозрачностей заводи `--brass-rgb: 210,183,115` рядом с hex-токеном и пиши `rgba(var(--brass-rgb), .3)`. Иначе `rgba(#hex,…)` разъезжается с токеном — линтер это ловит постфактум, а канальный токен решает в источнике. Заведи `-rgb`-дубль каждому цвету, который идёт в полупрозрачности.

## 2. Шрифты

Три бренд-шрифта (латиница+кириллица), у каждого — своя роль. **Роль перепутать = нечитаемо.**

| Шрифт | Только для |
|---|---|
| **Nolde** | КРУПНЫЕ заголовки — h1 страницы, название комплекса, заголовок экрана |
| **21 Cent** | основной читаемый текст — описания, абзацы, повествование |
| **20 Kopeek** | подписи, метаданные, теги, цифры/годы, мелкие технические тексты |

**Частая ошибка:** Nolde в подзаголовке или описании карточки — визуально «дорого», фактически нечитаемо. Описание → 21 Cent (повествовательное) или 20 Kopeek (техническое). **Nolde никогда ниже заголовочного уровня.**

**Не-латиница** (китайский, арабские, индийские и пр.): вендоренный сабсет **Noto** под фактический словарь (не весь шрифт). Всё локально, офлайн.

**Текст в canvas/текстурах — мерить по `actualBoundingBox`, не по кеглю.** Сложные письменности (тибетская, индийские, арабская) вылезают за em-box; offscreen-canvas под глиф размеряй по `actualBoundingBoxAscent/Descent/Left/Right` + поля, иначе обрезка. Фиксированный кегль как размер текстуры — гарантированный клиппинг.

## 3. Тач-геометрия (числа канонические, для 3840; в коде — переменные, не хардкод)

| Что | Значение | Токен |
|---|---|---|
| Минимальный интерактив | **64×64 px** | `--touch-min` |
| Основные контролы (нав, режимы, фильтры) | **96×96 px** | `--touch-primary` |
| Зазор между соседними | **≥ 16 px** | — |
| Отступ от кромки панели | **≥ 64 px** | `--edge-safe` |
| Отступ от НИЖНЕЙ кромки | **≥ 80 px** | `--edge-safe-bottom` (рамка + ладонь) |
| Кегль подписи/легенды | **≥ 24 px** | `--type-min-label` |
| Кегль текста на кнопке/чипе | **≥ 32 px** | `--type-min-ui` |

- **Чипы, легенды, контролы — в безопасной зоне, не по углам впритык.** Прижатое к краю не нажимается ладонью.
- **Скролл виден ВСЕГДА** (не auto-hide): 18 px, латунь на полупрозрачном треке. Скрытый скролл = посетитель не догадается, что есть ещё контент.
- **Призыв к жесту обязателен там, где есть жест.** Зум → «щипок», пан → «тяните», свайп → «листайте». Видна при простое, гаснет по первому касанию, возвращается через ~30 с бездействия. Самодельные подсказки заменить единым компонентом.

## 4. Масштаб и адаптивность

**Два независимых масштаба — не один.** Развязка снимает целый класс споров «×2 чего именно»:
- `--ui-scale` — размер интерфейсного хрома (кнопки, нав, подписи). Оператор настраивает; режим слабовидящих умножает на 1.25.
- `--content-scale` — плотность/размер контента сцены. Отдельная ручка.

Действующий `--ui-scale` — **произведение** (операторский × a11y-множитель), а не сумма и не max. Считай так, иначе «a11y почти не вырос» на ровном месте.

**Режим слабовидящих** (кнопка рантайма, сброс по idle): типографика ×1.5, контраст-тема без полупрозрачностей (paper на тёмном, латунь → ярче), анимации приглушены, тач-таргеты ×1.25, декор-слои прячутся, плотность контента снижается. Не «тема поверх», а полноценная перевёрстка — проверять её надо реальным переключением, не подстановкой класса (см. §7).

**Ориентация.** Целевая — вертикаль 2160×3840. Адаптация — забота владельца экрана; превью-инструмент должен показывать обе ориентации.

## 5. Контролы и паттерны (единый вид во всех проектах)

- **Поиск/отбор — единый «финдер», не постоянная колонка.** Вызывается видимой иконкой (лупа ≥96px), панель выезжает слоем поверх сцены, закрывается тапом мимо/крестом/idle. Декларация сцены: `search / filters / sorts`; состояние держит ядро, один метод применяет всё целиком.
  - **Список ≠ пространственная сцена.** У списка постоянная боковая колонка = буквальный дубль панели финдера → убрать, весь отбор в лупу. У карты/глобуса 2-3 чипа оси лежат ПОВЕРХ содержимого органично (не дубль) → остаются. Критерий: «колонка буквально повторяет панель?» да → убрать, нет → ярлык.
  - **Вид ≠ отбор.** Если контент разложен по некой оси как СМЫСЛ сцены (например листы по длине) — это порядок сцены, не критерий сортировки; не давать сортировку, которая ломает концепцию.
  - **Числа/подписи считать по ОТОБРАННОМУ**, не по всему корпусу — иначе «19 стран» спорит со стеной после фильтра. Пустой отбор → честная заглушка, не молча пустой экран.
- **Активное состояние — латунь** (см. §1). Чип/таб/кнопка выбраны = латунь, не красная заливка.
- **Однотипные контролы — одинаковы по виду и месту во всех экранах.** Размеры и скролл из общего кита, палитра из §1.
- **Карты — только вектор** (geojson + каноничная проекция), фото-подложки на плоских картах убрать. Исключение — сферические глобусы (там текстуры допустимы).

## 6. Архитектура киоск-приложения (платформенный слой)

Каждое приложение — **единая страница со сценами**, не набор страниц:
- **Сцены вместо страниц**, контракт `mount/unmount/pause/resume/reset/setLang/setA11y`. Переключение — кроссфейд без перезагрузки; ассеты преролятся один раз на старте (сплэш с прогрессом).
- **Standby** при простое (деф. 180 с): аттрактор-заставка из материала самого экспоната + «Коснитесь экрана»; FPS ≤ 10; касание → дефолтная сцена в дефолтном состоянии.
- **Idle-сброс** при простое (деф. 90 с): снять отбор/зум/карточки, язык → базовый. **Открытые карточки/оверлеи таймер НЕ замораживают** — ушедший посетитель не должен оставить киоск в своём состоянии. `reset()` — единая граница визита (и idle, и standby зовут его до аттрактора).
- **Языки** через словари (`i18n/*.json`), хардкод строк запрещён; переключатель — компонент рантайма; не-латиница — вендоренный Noto-сабсет. Контентные переводы — поля `{ru, en?, zh?}` с фолбэком.
- **Настройки — внутри приложения** (сервис-панель под гейтом), не в общем хабе. Сцена декларирует свои параметры схемой `settings:[…]` + `applySettings()` — ядро само рисует их в панели, хранит, сбрасывает. Кастомных панелей настроек в приложениях не заводить.

Общий фундамент — **вынесенный «кит»/ядро** (одна idle-машина, настройки, i18n, a11y, переключатель сцен, финдер, скролл, призыв к жесту, тач-переменные). Один код на всех — контролы выглядят и ведут себя одинаково. Держит ядро одна ответственная за него роль; прикладные экраны его не форкают.

## 7. Тех-инварианты офлайн-4K-киоска

- **Ноль сети в рантайме.** Никаких CDN-импортов (`esm.sh`, `jsdelivr`, `unpkg`, `cdnjs`, `skypack`), `<iframe src>` на внешнее, `fetch`, `Image.src` на удалённое, `@import` по сети. Все библиотеки **вендорятся локально** (бандл в `vendor/`), подключаются классическим `<script>` или локальным импортом. Прецедент: карта тянула d3 с CDN → на офлайн-стенде пустой canvas. Линтер должен падать на живом CDN.
- **Перф.** Неактивная сцена: **0 rAF / 0 таймеров**. Буфер ≤ 8.3 Мп, цель 60 fps. Watchdog + журнал ошибок в localStorage; ночной авторестарт (гигиена памяти).
- **WebGL — точечно, не по умолчанию.** Разрешён для арт-качества на 4K (глубина, объём — 3D-глобусы, художественный рендер) **при обязательном вендоринге**. Для 2D-карт/списков/картотек — Canvas 2D достаточно, WebGL избыточен. Бери там, где арт-плотность оправдывает вес.
- **Кеш-метки обязательны.** Chrome кеширует агрессивно; без `?v=<версия>` правка не доедет до киоска. При смене общего ядра — поднять метку ядра у ВСЕХ приложений (иначе киоск с закешированным старым файлом не получит фикс).

## 8. Доктрина проверки — «мерь фактическое, не предсказанное»

Это **главный дифференциатор** и самый переносимый раздел. Офлайн-4K-киоск наказывает за проверку предсказанного вместо фактического; ниже — принципы, выведенные граблями (независимо подтверждены соседним проектом — значит не вкусовые).

- **Замер, сверенный сам с собой, доказывает ДЕТЕРМИНИРОВАННОСТЬ, а не ПРАВИЛЬНОСТЬ.** Идеальный round-trip (`f(g(x))==x`) доказывает, что перевод обратим, но НИЧЕГО — про то, совпал ли результат с тем, что реально нарисовано. Проверять надо **фактический артефакт**, сверкой двух независимых сторон, а не функцию с собой.
  - *Цена ошибки в этом проекте:* фикс координат карты дал round-trip 0px (кружок↔тап консистентны) — и при этом кружки разъезжались со странами до 1898px, потому что база и кружки шли разными путями рендера. Поймали только сверкой ФАКТИЧЕСКОГО `ctx.getTransform()` двух сторон, с фальсификацией (заведомо сломанный вариант обязан давать большое расхождение — иначе ноль ничего не стоит).
- **Мерь пиксель, не CSS.** Фактический фон под текстом — скриншотом, а не предсказанием по CSS (CSS врёт на градиентах/наложениях). Контраст — пиксельным чекером.
- **Мерь попаданием, не стилями.** Тач-цель достижима? — `elementFromPoint` в точку, а не «по стилям должно быть 96px». Стиль и реальный хит расходятся (перекрытия, z-index, transform).
- **Фоновая/скрытая вкладка ВРЁТ.** rAF не тикает, ResizeObserver не доставляет, CSS-переходы застывают, время растянуто. Любой «зелёный» результат, зависящий от кадров, в скрытой вкладке — НЕ получен. Первичное состояние (размеры) снимать синхронно из штатного пути отрисовки, не с кадра.
- **Бокс 0×0 / не-разложенный layout глушит класс падений.** Считать масштаб/позицию против ещё-нулевого бокса → деление на ~0 → схлоп. Гард на ОБЕ оси (не только ширину); мерить после того, как элемент получил реальный бокс.
- **Деливерабл ≠ промежуточная метрика.** Проверяй то, что видит посетитель (поле сцены, позицию кружка), а не удобную внутреннюю величину (высоту нава, номер уровня). Промежуток может быть верным, пока деливерабл сломан.
- **Проверять в РАЗРЕШЕНИИ КИОСКА (4K), на видимом экране.** Инструмент проверки, схлопнутый в маленькое окно, врёт «сломано» на исправном коде. При выводе «прод сломан» — сперва проверь размер вьюпорта и число вкладок инструмента; дублируй серверной проверкой (реальные байты, HTTP-код), она не зависит от рендера.
- **Молчаливый зелёный хуже отсутствия проверки.** Инструмент, отдающий «ок» на схлопнутом окне / нулевом боксе / неприменимом случае, обязан ОТКАЗАТЬСЯ вслух. Три исхода (ок / провал / неприменимо) различать явно — `ok:null` ≠ провал.

**Инструменты этого класса** (падают на приросте, не на наличии; самодостаточные): линтер бренда (сырой hex, курсив бренд-шрифта, живой CDN, `var(--x,#hex)`), пиксельный контраст-чекер (`--self-test`), тач-цель попаданием, перебор сочетаний настроек с контент-независимыми инвариантами. Держать их в репо, гонять до сдачи.

## Как этим пользоваться

1. **Токены (§1) и шрифты (§2)** — копируются напрямую, это база.
2. **Геометрия (§3), масштаб (§4), контролы (§5)** — переносимые правила; адаптируй числа под свою среду, но принципы держи.
3. **Архитектура (§6) и тех-инварианты (§7)** — если ты тоже офлайн-4K-киоск, берёшь целиком; иначе — §7 (сеть/перф) и §8 остаются в силе, §6 по применимости.
4. **Доктрина проверки (§8)** — универсальна для любой визуальной среды; самый ценный раздел, берётся всегда.

Источник правил дизайнера — `COORDINATION.md` → «Шрифтово-цветовые правила» (редакция 2026-05-12) и «Тач-стандарт» / «Киоск-стандарт v2». Грабли с воспроизведением — `GRABLI.md`. Архитектура сцен — `PLAN-KIOSK.md`.
