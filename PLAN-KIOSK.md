# PLAN-KIOSK — киоск-платформа BMK 38-42

План перехода от прототипов к музейной киоск-платформе. Решение пользователя 2026-08-02.
Канонические требования — COORDINATION.md → «Киоск-стандарт» (v2). Здесь — архитектура и фазы.

## Целевая картина

Каждый МТК — **единое автономное приложение** (`mtkXX-app/`), которое:
- держит все свои экраны-варианты как **сцены** внутри одной страницы — переключение без перезагрузки, плавное (кроссфейд), ассеты преролятся один раз на старте;
- **самодостаточно**: свои кнопки навигации сцен, свои настройки (положение/размер кнопок, косая подложка, тайминги), стендбай, idle-сброс, языки, режим слабовидящих — всё внутри, хаб не нужен;
- работает в двух контекстах: **standalone** (музейный киоск, Chrome --kiosk, полный офлайн) и **внутри хаба** (демо/разработка — хаб становится лаунчером).

Общий фундамент — **киоск-рантайм** `assets/shared/kiosk/` (зона координатора): один код idle-машины, настроек, i18n, a11y и переключателя сцен на всех.

## Контракт сцены (kiosk-core, v1)

Вариант = модуль-сцена, регистрируется в приложении МТК:

```js
KioskApp.registerScene({
  id: "map",                       // slug сцены
  title: { ru: "Карта", en: "Map", zh: "地图" },
  mount(el, ctx) {},               // построить DOM/canvas в el; ctx: {lang, a11y, settings, data}
  unmount() {},                    // полностью снять (без утечек!)
  pause() {},                      // сцена не видна: остановить rAF/таймеры
  resume() {},                     // сцена снова видна
  reset() {},                      // idle-сброс: снять фильтры/зум/карточки, вернуть дефолт
  setLang(lang) {},                // ru | en | zh
  setA11y(on) {},                  // режим слабовидящих
  standby() { return null; },      // опц.: своя аттрактор-петля (иначе общий аттрактор app)

  /* Настройки СЦЕНЫ (v1.2): декларация — ядро само рисует их в сервис-панели
   * группой «Настройки МТК · <сцена>», хранит поверх дефолтов и отдаёт сцене. */
  settings: [                      // опц.
    { key: "dotSize", label: { ru: "Размер точек" }, type: "range",
      min: 0.5, max: 3, step: 0.1, default: 1 },
    { key: "labels",  label: { ru: "Подписи" }, type: "toggle", default: true },
  ],
  applySettings(values) {},        // вызывается на старте и при каждом изменении

  /* Посетительские состояния (v1.8): фильтры и режимы, которых нет в схеме
   * настроек оператора. Нужны перебору состояний (tools/sweep.js), который
   * зовёт healthcheck() на каждом и ловит «сцена краснеет на законном экране».
   * Ядро этот метод не вызывает; сцены без него перебираются по схеме. */
  states() { return []; },         // опц.: [{ name, apply() }]; ПЕРВОЕ = дефолтное
  restoreState() {},               // опц.: вернуть посетительское состояние после
                                   // перебора. Нет — берётся первое из states();
                                   // нет и его — состояние остаётся, и это дефект:
                                   // посетитель видит следы сервиса до idle-сброса
  applyAppSettings(values) {},     // опц.: настройки УРОВНЯ ПРИЛОЖЕНИЯ (appSettings
                                   // в createApp) — приходят всем сценам сразу
});
```

Настройки, эффект которых принадлежит не сцене, а приложению (общий цвет фото у
двух сцен), объявляются в `createApp({ appSettings: [...] })` той же схемой и
живут в `app.<key>`: в сцене такая настройка либо врёт подписью, либо двоится.

Хранение настроек сцен: `localStorage["mtkXX-kiosk"].scenes[id]` поверх дефолтов схемы;
кнопка «Сбросить» в панели возвращает дефолты. Так тюнинг-панели старых прототипов
переезжают в единое место — сервис-панель, у всех МТК одинаково.

Состав и порядок экранов лежат **отдельно** — `screens.order` / `screens.enabled`:
в общем объекте с настройками сцена с id `order` затёрла бы состав.

`KioskApp` (ядро) владеет: реестром сцен, кроссфейд-переключением (два слоя, fade 300–400 мс,
без белых вспышек), прероллом (данные+шрифты+изображения всех сцен на старте, сплэш с прогрессом),
idle-машиной, панелью настроек (гейт `?service=1`), языковым слоем, a11y, полосами фона.

## Idle-машина (единая, настраиваемая)

```
ACTIVE --T_reset (деф. 90 с)--> RESET (сцены.reset(): фильтры/зум/карточки/язык→RU)
ACTIVE --T_standby (деф. 180 с)--> STANDBY (аттрактор: медленная петля + «Коснитесь экрана»)
STANDBY --касание--> ACTIVE (дефолтная сцена, дефолтное состояние)
```
- Тайминги и дефолтная сцена — в `mtkXX-app/kiosk.config.json` + правятся из сервис-панели.
- В STANDBY: FPS ≤ 10, WebGL-сцены выгружены или на паузе (экономия GPU, отсутствие выжигания).
- Ночной автоперезапуск страницы (деф. 04:00) — гигиена памяти.

## Языки (RU / EN / ZH)

- Переключатель — компонент рантайма (три подписи «РУС · ENG · 中文»), позиция из настроек,
  сброс на RU по idle-reset.
- **Этап A (обязательный): UI-хром** — все интерфейсные строки через словари
  `mtkXX-app/i18n/{ru,en,zh}.json`; хардкод строк в разметке/JS запрещается.
- **Этап B (контент)**: названия объектов/рубрик/эпох, описания, цитаты — отдельное решение
  с куратором (объём перевода). Схема данных готовится: контентные поля становятся
  `{ru, en?, zh?}`-объектами с фолбэком на ru.
- Шрифты: EN покрыт брендовыми; ZH — сабсет Noto Sans SC под фактический словарь
  (пайплайн `assets/shared/fonts/` + build_fonts.py уже есть). Всё вендорится, офлайн.

## Режим слабовидящих

- Кнопка рантайма (значок-глаз, ≥96 px), сброс по idle.
- Что меняет (v1): типографика ×1.5 (через `--a11y-scale`), контраст-тема (без полупрозрачностей,
  paper-на-чёрном, латунь → жёлтый #FFD24A), анимации приглушены (reduced-motion),
  тач-таргеты ×1.25, фокус на главном контенте (декор-слои прячутся).
- Реализация: класс `.a11y` на `<html>` + токены; сцены дополнительно реагируют в `setA11y()`
  (крупнее точки на картах, меньше плотность подписей).

## Настройки — внутрь МТК (из хаба)

- Панель настроек (⚙) переезжает в рантайм приложения: позиция/яркость/размер кнопок навигации,
  косая подложка (вкл/яркость), тайминги idle, дефолтный язык, дефолтная сцена.
- Хранение: `localStorage["mtkXX-kiosk"]` поверх дефолтов из `kiosk.config.json` (конфиг в git —
  переживает очистку браузера).
- Гейт: `?service=1` или тройной тап по заголовку (паттерн уже принят). Посетителю панель недоступна.
- Хаб после миграции всех МТК: его стрелки/⚙/полосы удаляются, остаётся лаунчер пяти приложений.

## Финдер: поиск / отбор / сортировка (решение пользователя 2026-08-06)

Во всех МТК — единый механизм поиска, отбора и сортировки по образцу картотеки 40,
но **не висящий на экране постоянно**: вызывается отдельной, хорошо видимой иконкой
(лупа в хроме ядра рядом с переключателем языков, ≥96 px). Панель выезжает слоем
поверх сцены и не захламляет её; закрывается тапом мимо, крестом и idle-сбросом.

Реализация — компонент кита + декларация сцены (по образцу settings[]/states()):

```js
finder: {                          // опц.: сцена объявляет, чем можно искать
  search: { fields: [...], apply(q) {} },       // текстовый поиск
  filters: [ { key, label, options, apply() } ],// отбор чипами (что уже есть — переезжает)
  sorts:   [ { key, label, apply() } ],         // сортировка
}
```

- Ядро рисует иконку ТОЛЬКО сценам, объявившим finder; счётчик активного отбора
  на иконке (лупа + точка), чтобы «почему так мало объектов» не был загадкой.
- Текстовый ввод — экранная клавиатура кита (вендорена, офлайн): раскладки RU/EN;
  в ZH-интерфейсе поиск теми же полями (канон данных — ru/латиница), с пояснением
  в панели. Пиньинь-IME не делаем.
- Сброс отбора — idle-reset (канон), кнопка «Сбросить» в панели, и сброс при
  уходе со сцены НЕ делаем — отбор живёт в сцене до idle (паттерн класса Б).
- a11y: панель и клавиатура растут от --ui-scale; иконка в замере зон хрома.

Фазы: спецификация — координатор (эта секция); компонент — kiosk-core (иконка,
панель, клавиатура, контракт); пилот финдера — МТК 39 (1203 записи — самый
выигрышный поиск); тираж — 38/41/42; 40 сверяет свою картотеку с паттерном
(его боковая колонка остаётся, финдер добавляет поиск).

## Оптимизация: нагрузка и автономность

Перф-бюджеты (проверяются тач-аудитом):
- рендер-буфер ≤ 8.3 Мп (уже канон), 60 fps цель / 30 минимум на киоск-железе;
- неактивная сцена не потребляет: 0 rAF, 0 таймеров (lifecycle pause обязателен);
- преролл на старте; дальше — НОЛЬ СЕТЕВЫХ обращений (внешние хосты запрещены абсолютно).
  Локальные (same-origin) дисковые догрузки допустимы точечно — полноразмерное фото по тапу
  и т.п.; приёмка различает локальный путь и внешний хост (правка 2026-08-04 по находке 41:
  запрет диска был ошибкой — фотокорпус 282 снимка это 19 МБ на диске, но 7,8 ГБ декодированными,
  преролл оригиналов невозможен физически);
- тяжёлые фотокорпуса — ТИРАМИ: миниатюры (~480 px) в преролл, полноразмер (900–1200 px)
  догружается по тапу с локального диска; оригиналы сверх 1200 px в киоск не кладутся;
- утечки: 50 циклов переключения всех сцен без роста JS heap (проверка в аудите).

Автономность:
- ноль обращений в сеть (аудит-скрипт координатора: `<iframe src=http`, `fetch(http`,
  `new Image` c внешним хостом, `@import url(http`, `href=http` в CSS/JS/HTML);
- watchdog в рантайме: сцена не отвечает > N с → перезапуск приложения; JS-ошибки копятся
  в `localStorage`-журнал (смотрится из сервис-панели);
- киоск-обвязка (этап 7 PLAN.md): автозапуск Chrome --kiosk, автоперезапуск при краше, запрет сна.
