# PLAN-KIOSK — киоск-платформа BMK 38-42

План перехода от прототипов к музейной киоск-платформе. Решение пользователя 2026-08-02.
Канонические требования — COORDINATION.md → «Киоск-стандарт» (v2). Здесь — архитектура и фазы.

## Целевая картина

Каждый МТК — **единое автономное приложение** (`mtkXX-app/`), которое:
- держит все свои экраны-варианты как **сцены** внутри одной страницы — переключение без перезагрузки, плавное (кроссфейд), ассеты преролятся один раз на старте;
- **самодостаточно**: свои кнопки навигации сцен, свои настройки (положение/размер кнопок, косая подложка, тайминги), стендбай, idle-сброс, языки, режим слабовидящих — всё внутри, хаб не нужен;
- работает в двух контекстах: **standalone** (музейный киоск, Chrome --kiosk, полный офлайн) и **внутри хаба** (демо/разработка — хаб становится лаунчером).

Общий фундамент — **киоск-рантайм** `assets/shared/kiosk/` (зона координатора): один код idle-машины, настроек, i18n, a11y и переключателя сцен на всех.

## Контракт сцены (kiosk-core, v1)

Вариант = модуль-сцена, регистрируется в приложении МТК:

```js
KioskApp.registerScene({
  id: "map",                       // slug сцены
  title: { ru: "Карта", en: "Map", zh: "地图" },
  mount(el, ctx) {},               // построить DOM/canvas в el; ctx: {lang, a11y, settings, data}
  unmount() {},                    // полностью снять (без утечек!)
  pause() {},                      // сцена не видна: остановить rAF/таймеры
  resume() {},                     // сцена снова видна
  reset() {},                      // idle-сброс: снять фильтры/зум/карточки, вернуть дефолт
  setLang(lang) {},                // ru | en | zh
  setA11y(on) {},                  // режим слабовидящих
  standby() { return null; },      // опц.: своя аттрактор-петля (иначе общий аттрактор app)

  /* Настройки СЦЕНЫ (v1.2): декларация — ядро само рисует их в сервис-панели
   * группой «Настройки МТК · <сцена>», хранит поверх дефолтов и отдаёт сцене. */
  settings: [                      // опц.
    { key: "dotSize", label: { ru: "Размер точек" }, type: "range",
      min: 0.5, max: 3, step: 0.1, default: 1 },
    { key: "labels",  label: { ru: "Подписи" }, type: "toggle", default: true },
  ],
  applySettings(values) {},        // вызывается на старте и при каждом изменении

  /* Посетительские состояния (v1.8): фильтры и режимы, которых нет в схеме
   * настроек оператора. Нужны перебору состояний (tools/sweep.js), который
   * зовёт healthcheck() на каждом и ловит «сцена краснеет на законном экране».
   * Ядро этот метод не вызывает; сцены без него перебираются по схеме. */
  states() { return []; },         // опц.: [{ name, apply() }]; ПЕРВОЕ = дефолтное
  restoreState() {},               // опц.: вернуть посетительское состояние после
                                   // перебора. Нет — берётся первое из states();
                                   // нет и его — состояние остаётся, и это дефект:
                                   // посетитель видит следы сервиса до idle-сброса
  applyAppSettings(values) {},     // опц.: настройки УРОВНЯ ПРИЛОЖЕНИЯ (appSettings
                                   // в createApp) — приходят всем сценам сразу
});
```

Настройки, эффект которых принадлежит не сцене, а приложению (общий цвет фото у
двух сцен), объявляются в `createApp({ appSettings: [...] })` той же схемой и
живут в `app.<key>`: в сцене такая настройка либо врёт подписью, либо двоится.

Хранение настроек сцен: `localStorage["mtkXX-kiosk"].scenes[id]` поверх дефолтов схемы;
кнопка «Сбросить» в панели возвращает дефолты. Так тюнинг-панели старых прототипов
переезжают в единое место — сервис-панель, у всех МТК одинаково.

Состав и порядок экранов лежат **отдельно** — `screens.order` / `screens.enabled`:
в общем объекте с настройками сцена с id `order` затёрла бы состав.

`KioskApp` (ядро) владеет: реестром сцен, кроссфейд-переключением (два слоя, fade 300–400 мс,
без белых вспышек), прероллом (данные+шрифты+изображения всех сцен на старте, сплэш с прогрессом),
idle-машиной, панелью настроек (гейт `?service=1`), языковым слоем, a11y, полосами фона.

## Idle-машина (единая, настраиваемая)

```
ACTIVE --T_reset (деф. 90 с)--> RESET (сцены.reset(): фильтры/зум/карточки/язык→RU)
ACTIVE --T_standby (деф. 180 с)--> STANDBY (аттрактор: медленная петля + «Коснитесь экрана»)
STANDBY --касание--> ACTIVE (дефолтная сцена, дефолтное состояние)
```
- Тайминги и дефолтная сцена — в `mtkXX-app/kiosk.config.json` + правятся из сервис-панели.
- В STANDBY: FPS ≤ 10, WebGL-сцены выгружены или на паузе (экономия GPU, отсутствие выжигания).
- Ночной автоперезапуск страницы (деф. 04:00) — гигиена памяти.

## Языки (RU / EN / ZH)

- Переключатель — компонент рантайма (три подписи «РУС · ENG · 中文»), позиция из настроек,
  сброс на RU по idle-reset.
- **Этап A (обязательный): UI-хром** — все интерфейсные строки через словари
  `mtkXX-app/i18n/{ru,en,zh}.json`; хардкод строк в разметке/JS запрещается.
- **Этап B (контент)**: названия объектов/рубрик/эпох, описания, цитаты — отдельное решение
  с куратором (объём перевода). Схема данных готовится: контентные поля становятся
  `{ru, en?, zh?}`-объектами с фолбэком на ru.
- Шрифты: EN покрыт брендовыми; ZH — сабсет Noto Sans SC под фактический словарь
  (пайплайн `assets/shared/fonts/` + build_fonts.py уже есть). Всё вендорится, офлайн.

## Режим слабовидящих

- Кнопка рантайма (значок-глаз, ≥96 px), сброс по idle.
- Что меняет (v1): типографика ×1.5 (через `--a11y-scale`), контраст-тема (без полупрозрачностей,
  paper-на-чёрном, латунь → жёлтый #FFD24A), анимации приглушены (reduced-motion),
  тач-таргеты ×1.25, фокус на главном контенте (декор-слои прячутся).
- Реализация: класс `.a11y` на `<html>` + токены; сцены дополнительно реагируют в `setA11y()`
  (крупнее точки на картах, меньше плотность подписей).

## Настройки — внутрь МТК (из хаба)

- Панель настроек (⚙) переезжает в рантайм приложения: позиция/яркость/размер кнопок навигации,
  косая подложка (вкл/яркость), тайминги idle, дефолтный язык, дефолтная сцена.
- Хранение: `localStorage["mtkXX-kiosk"]` поверх дефолтов из `kiosk.config.json` (конфиг в git —
  переживает очистку браузера).
- Гейт: `?service=1` или тройной тап по заголовку (паттерн уже принят). Посетителю панель недоступна.
- Хаб после миграции всех МТК: его стрелки/⚙/полосы удаляются, остаётся лаунчер пяти приложений.

## Финдер: поиск / отбор / сортировка (решение пользователя 2026-08-06)

Во всех МТК — единый механизм поиска, отбора и сортировки по образцу картотеки 40,
но **не висящий на экране постоянно**: вызывается отдельной, хорошо видимой иконкой
(лупа в хроме ядра рядом с переключателем языков, ≥96 px). Панель выезжает слоем
поверх сцены и не захламляет её; закрывается тапом мимо, крестом и idle-сбросом.

Реализация — компонент кита + декларация сцены (по образцу settings[]/states()):

```js
finder: {                          // опц.: сцена объявляет, чем можно искать
  search: { fields: [...] },                    // текстовый поиск
  filters: [ { key, label, options } ],         // отбор; options — массив ИЛИ функция
  sorts:   [ { key, label } ],                  // сортировка
},
applyFinder({ query, filters, sort }) {},       // КАНОН: состояние держит ЯДРО и зовёт
                                                // ОДИН метод целиком при любом изменении;
                                                // порядок применения: отбор → поиск →
                                                // сортировка. Возврат {shown, total} —
                                                // опционален, для строки «N из M» в панели.
```

- Пер-пунктовые apply() — опциональный сахар для простых случаев, канон — applyFinder.
- В финдер переезжает ОТБОР (фильтры-чипы, сужающие выборку). Переключения ВИДА/режима
  («глобус/карта», раскладки) — главные взаимодействия сцены и остаются на сцене:
  за два касания их не прячут. Финдер объявляют только сцены, где поиск осмыслен, —
  не везде ради единообразия. Панель вертикальна и прокручивается: ограничение
  «чипы съедают экран» она не переносит, а снимает — options функцией можно отдавать
  ПОЛНЫЙ набор категорий, даже если сцена чипами показывала усечённый.
- Ядро рисует иконку ТОЛЬКО сценам, объявившим finder. На иконке — точка с числом
  активных КРИТЕРИЕВ (ядро знает само, обязанностей у сцен ноль); «N из M» — внутри
  панели, если applyFinder вернул числа. Точка отвечает «отбор включён», панель —
  «что именно и сколько осталось».
- Состояние финдера ядро гасит ДО вызова reset() сцены; отбор финдера входит в
  states() — иначе класс состояний выпадает из приёмки.
- Текстовый ввод — экранная клавиатура кита (вендорена, офлайн): раскладки RU/EN;
  в ZH-интерфейсе поиск теми же полями (канон данных — ru/латиница), с пояснением
  в панели. Пиньинь-IME не делаем.
- Сброс отбора — idle-reset (канон), кнопка «Сбросить» в панели, и сброс при
  уходе со сцены НЕ делаем — отбор живёт в сцене до idle (паттерн класса Б).
- Уточнение (2026-08-10): **граница визита — заставка.** Отбор переживает уход
  и возврат В ПРЕДЕЛАХ визита; вход в standby чистит финдер-состояние ВСЕХ сцен
  (query, фильтры, сортировка — к декларации), закрывает панель и гасит точку.
  Посетитель №2 не должен разгадывать фильтр посетителя №1: «N из 1203» объясняет
  пустой шар тому, кто фильтр ставил, — не тому, кто подошёл следом.
- Панель принадлежит СЦЕНЕ, не приложению (урок 1.17.2): уход со сцены закрывает
  панель; на другой финдер-сцене она строится заново по ЕЁ декларации — включая
  клавиатуру и поле ввода (не по первому spec.search).
- **Ярлык в финдер** (канон по пилоту 39, 2026-08-10): элемент сцены может быть
  ярлыком конкретного критерия — тап шлёт тот же ПАТЧ, что выбор значения в
  панели; повторный тап ярлыка шлёт null (снятие). У панельных чипов семантика
  иная — там значение выбирают, а снимают чипом «—»: ярлык — переключатель,
  чип — выбор из ряда, и это расхождение осознанное (уточнение по вердикту
  скептика 2026-08-10). Состояние по-прежнему живёт только в
  ядре, копий на сцене нет; точка на лупе — единственный индикатор включённого
  отбора. Ярлык — полноценный контрол: тач-пол ≥64, участие в замере зон,
  видимая реакция нажатия. Родился из ловушки пилота: легенда, выглядящая как
  бывший чип, но с pointer-events:none, — ложный аффорданс; отбор, стоивший
  одного касания, не должен дорожать до двух из-за переезда в финдер.
  Счёт на ярлыке — ФАСЕТНЫЙ: по всем критериям, кроме собственной оси
  («число на строке = сколько будет, если выбрать эту») — иначе при выбранном
  значении соседние строки показывают 0 и читаются отключёнными ровно тогда,
  когда нужны; без активного фильтра фасетный счёт совпадает с полным.
- a11y: панель и клавиатура растут от --ui-scale; иконка в замере зон хрома.

Фазы: спецификация — координатор (эта секция); компонент — kiosk-core (иконка,
панель, клавиатура, контракт); пилот финдера — МТК 39 (1203 записи — самый
выигрышный поиск); тираж — 38/41/42; 40 сверяет свою картотеку с паттерном
(его боковая колонка остаётся, финдер добавляет поиск).

## Зум жестом: интерфейс НЕ зумится, контент — да (решение пользователя 2026-08-10)

На киоске **страница/интерфейс не масштабируется никогда** (браузерный зум — дефект: посетитель растянет весь UI). Но жест зума не глушим, а **уводим на контент**: где есть пространственный интерактив (глобусы, карты) — pinch/колесо приближают САМ контент (камеру сцены), не страницу.

- Подавление нативного зума — ЯДРО (оболочка рантайма): gesturestart/gesturechange preventDefault, wheel+ctrlKey preventDefault, dblclick, meta user-scalable=no; `visualViewport.scale ≡ 1`. Ядро гасит нативный зум, но НЕ крадёт жест у канв — сцена ловит сырые события сама.
- Зум контента — СЦЕНА (у кого есть гео/3D): pinch (2 касания, по расстоянию между ними) ИЛИ wheel → зум камеры/проекции своего контента. Канон жеста: **нижняя граница зума = «весь контент вписан в кадр»** (fit-to-content, НЕ магическое число — «дальше отдалять некуда» совпадает с кнопкой «Весь вид», а не пускает в пустоту; формулировка 41); верхняя — разумный предел приближения; pan и zoom считать РАЗДЕЛЬНО за кадр (сдвиг середины пальцев → камера, изменение расстояния → зум — иначе двупальцевый перенос без изменения расстояния даёт ноль); 1-палец остаётся drag-rotate/pan; тап-карточка жив (порог TAP_THRESHOLD, при drag тап не стреляет); **сброс зума на границе визита** (standby/idle-reset — как отбор финдера); pinch увязан с кнопками вида сцены («Отдалить»/«Весь вид»/«сбросить масштаб») ОДНИМ стейтом, не вторым параллельным.
- Списки/картотеки/скрабберы/статичные сцены контент-зум НЕ объявляют — там щипок после подавления ИНЕРТЕН (ничего не делает, без poke-отклика: это не зависание, а отсутствие пространственного контента для зума).
- **Ядро гасит нативный зум, но НЕ крадёт жест у канв контент-зума:** двупальцевый touchmove на канве интерактивной сцены (touch-action:none) ДОХОДИТ до сцены — ядро preventDefault'ит браузерный дефолт (нет зума страницы), но не stopPropagation (сцена слушает и зумит контент сама). Подавление мультитач-зума ядром и pinch-зум контента сценой сосуществуют. Ядро ставит touch-action:none на канвы в `.kiosk-stage` само (страховка, если сцена забудет своё). На канве СЦЕНА вправе зумить любым wheel (не только Ctrl+wheel — это стандарт карт; ядро обычный wheel не трогает, отдаёт сцене).
- **fitZoom — helper ядра для нижней границы:** `KioskCore.fitZoom(contentW, contentH, viewW, viewH, {mode:"contain"|"cover", padding:0})` → минимальный масштаб «весь контент в кадре» (contain = min(vw/cw, vh/ch)). Ядро держит КРАЯ (контент/вьюпорт ≤ 0 → 1, padding зажат) — три карты не форкают формулу и не расходятся на делении на ноль. Верхнюю границу зума сцена держит сама. Все карты (39-union/40/41/42) зовут его.
- **Пол fitZoom — НЕ КОНСТАНТА (следствие 41, касается ВСЕХ карт):** высота стола меняется при resize и при a11y (нав растёт → стол ужимается → fit ПОДНИМАЕТСЯ). Helper даёт число, но пересчёт на `_resized()`/`setA11y()` И **докламп текущего зума к новому полу — на СЦЕНЕ**. Иначе посетитель, отдалившийся до предела в обычном режиме, после включения a11y останется НИЖЕ нового законного минимума — тихо, без ошибки. И: любой путь к зуму (включая пресеты вида) вести ЧЕРЕЗ кламп, не мимо.
- **Пол через ОТНОШЕНИЕ иммунен к resize/a11y (лучшая форма, 41):** если минимум зума выражен отношением к ЖИВОМУ размеру (напр. `MIN_ZOOM=1` = «весь диапазон вписан в текущую ширину», `_pxPerYear = usableW/TOTAL·zoom`), а не абсолютом — пол сам едет за ресайзом и a11y, пересчитывать и доклампывать НЕЧЕГО. Где можешь выразить пол отношением — выражай, это снимает весь класс «плавающего пола». Двумерный зум карты так не сводится (мир привязан к ширине, зум по обеим осям) — там пересчёт+докламп обязателен; одномерная ось (хронология) — сводится.
- **Одномерный пространственный контент ТОЖЕ объявляет зум:** ось (лет/шкала) с щипком-приближением и провалом вглубь (декада→год→объект) — тот же пространственный интерактив, что карта, просто 1D. Если подпись обещает щипок — инертным его делать НЕЛЬЗЯ (обман подписи). Классификация «списки не зумят» — про НЕпространственные списки (картотеки, тексты), не про оси.
- **Смена режима (a11y/resize) — НЕ граница визита (уточнение 40):** пересчёт fit НЕ должен СБРАСЫВАТЬ позицию/зум к «весь вид» — только пересчитать пол и доклампить (сохранив, где посетитель был). Граница визита (полный сброс) — только idle/standby (reset()). Различай: первый показ / reset / кнопка «весь вид» → полный fit; resize/a11y при уже показанной сцене → recompute-пол + докламп, позу НЕ трогать (флаг «fitted» различает).
- **reset() — единая граница визита; ЯДРО зовёт его на idle-сбросе И на входе в заставку (_enterStandby), ДО scene.standby().** Сброс зума/фильтров/открытых карточек/скролла — всё в reset(); отдельный standby-хук НЕ нужен и НЕ делается (был бы второй путь сброса того же). Без reset-на-standby аттрактор крутил бы приближённую карту №1 (standby<reset легально по timings) — «посетитель №2 видит зум №1» на заставке.
- touch-action: канвы интерактива = none (жест уходит в JS сцены), .kiosk-scroll = pan-y, корень хрома = none.

## Оптимизация: нагрузка и автономность

Перф-бюджеты (проверяются тач-аудитом):
- рендер-буфер ≤ 8.3 Мп (уже канон), 60 fps цель / 30 минимум на киоск-железе;
- неактивная сцена не потребляет: 0 rAF, 0 таймеров (lifecycle pause обязателен);
- преролл на старте; дальше — НОЛЬ СЕТЕВЫХ обращений (внешние хосты запрещены абсолютно).
  Локальные (same-origin) дисковые догрузки допустимы точечно — полноразмерное фото по тапу
  и т.п.; приёмка различает локальный путь и внешний хост (правка 2026-08-04 по находке 41:
  запрет диска был ошибкой — фотокорпус 282 снимка это 19 МБ на диске, но 7,8 ГБ декодированными,
  преролл оригиналов невозможен физически);
- тяжёлые фотокорпуса — ТИРАМИ: миниатюры (~480 px) в преролл, полноразмер (900–1200 px)
  догружается по тапу с локального диска; оригиналы сверх 1200 px в киоск не кладутся;
- утечки: 50 циклов переключения всех сцен без роста JS heap (проверка в аудите).

Автономность:
- ноль обращений в сеть (аудит-скрипт координатора: `<iframe src=http`, `fetch(http`,
  `new Image` c внешним хостом, `@import url(http`, `href=http` в CSS/JS/HTML);
- watchdog в рантайме: сцена не отвечает > N с → перезапуск приложения; JS-ошибки копятся
  в `localStorage`-журнал (смотрится из сервис-панели);
- киоск-обвязка (этап 7 PLAN.md): автозапуск Chrome --kiosk, автоперезапуск при краше, запрет сна.
