# kiosk-core — ядро киоск-приложения МТК

Общий рантайм для пяти музейных комплексов. Канон требований —
[PLAN-KIOSK.md](../../../PLAN-KIOSK.md) и COORDINATION.md → «Тач-стандарт киоска»,
«Киоск-стандарт v2». Здесь — как этим пользоваться.

**Зона.** `assets/shared/kiosk/**` ведёт сессия `kiosk-core`. Сессии МТК файлы ядра
не правят: нужна доработка — заявка через пользователя. Свои сцены, свой конфиг и
свои словари вы держите у себя в `mtkXX-app/`.

## Что даёт ядро

Реестр сцен и кроссфейд без перезагрузки · преролл ассетов со сплэшем · навигация
(титул, стрелки, точки) по тач-стандарту · косая подложка · idle-сброс и standby ·
ночной авторестарт · watchdog и журнал ошибок · i18n RU/EN/ZH · режим слабовидящих ·
сервис-панель с единым видом контролов.

Что остаётся вам: сами сцены и честное поведение в `pause()` / `reset()` / `setLang()` /
`setA11y()`.

## Раскладка приложения

```
mtk42-app/
  index.html
  app.js                 создаёт приложение, регистрирует сцены
  kiosk.config.json      дефолты киоска (в git — переживает очистку браузера)
  i18n/{ru,en,zh}.json   строки UI-хрома
  scenes/*.js            сцены
  styles.css             ваши стили
```

## index.html

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
    <title>МТК 42</title>
    <link rel="stylesheet" href="../assets/shared/kiosk/kiosk.css?v=1.21.2" />
    <link rel="stylesheet" href="../assets/shared/kiosk/kiosk-core.css?v=1.21.2" />
    <link rel="stylesheet" href="./styles.css?v=1.21.2" />
  </head>
  <body>
    <script type="module" src="./app.js?v=1.21.2"></script>
  </body>
</html>
```

`?v=` обязателен и равен ТОЧНОЙ версии ядра — см. «Канон версий кита» ниже.
Chrome кеширует статику агрессивно, и без метки правка может просто не доехать
до киоска.

Тело пустое — разметку строит ядро. Открывать **только по http** (`ES`-модули из
`file://` не работают).

## app.js

```js
// ?v= на обёртке прокидывается и на само ядро — поднимайте в одном месте
import { createApp } from "../assets/shared/kiosk/kiosk-core.esm.js?v=1.21.2";
import { mapScene } from "./scenes/map.js?v=1.21.2";        // импорты сцен тоже!
import { timelineScene } from "./scenes/timeline.js?v=1.21.2";

const app = createApp({
  appId: "mtk42",                       // ключ localStorage: "mtk42-kiosk"
  title: { ru: "МТК · 42", en: "MTK · 42", zh: "МТК · 42" },
  configUrl: "./kiosk.config.json",
  i18nUrl: "./i18n/",
  i18nVersion: "1.21.2",                 // метка кеша словарей — та же версия ядра
});

app.registerScene(mapScene);            // порядок регистрации = порядок стрелок
app.registerScene(timelineScene);

app.start();
```

Без сборщика и без модулей — то же самое классическим скриптом:

```html
<script src="../assets/shared/kiosk/kiosk-core.js?v=1.21.2"></script>
<script>
  const app = KioskCore.createApp({ appId: "mtk42", /* … */ });
</script>
```

## Контракт сцены

```js
export const mapScene = {
  id: "map",                                  // slug, уникален в приложении
  title: { ru: "Карта", en: "Map", zh: "地图" },

  keepAlive: true,      // деф.: смонтироваться один раз и жить на паузе.
                        // false — выгружаться при уходе (тяжёлые WebGL-сцены)
  watchdog: false,      // true — ядро следит, что сцена зовёт ctx.beat()

  preload: {            // грузится на старте, со сплэшем; в рантайме — ноль сети
    data:   { museums: "../data/mtk42.json" },     // → ctx.data.museums
    images: ["../assets/mtk42/portraits/01.jpg"],  // → ctx.images[url]
    fonts:  ["1em '20 Kopeek'"],
    // custom(ctx) { return somePromise; }
  },

  mount(el, ctx) {},    // построить DOM/canvas внутри el. ctx: {app, lang, a11y,
                        // settings, data, images, beat}. Можно вернуть промис —
                        // ядро дождётся его до старта кроссфейда
  unmount() {},         // снять всё: слушатели, ResizeObserver, таймеры
  pause() {},           // сцена не видна: ОСТАНОВИТЬ rAF и таймеры полностью
  resume() {},          // снова видна
  reset() {},           // idle-сброс: фильтры, зум, открытые карточки, скролл
  setLang(lang) {},     // "ru" | "en" | "zh"
  setA11y(on) {},       // крупнее точки, меньше плотность подписей
  standby() { return null; },  // см. ниже
};
```

Все методы необязательны — ядро зовёт только то, что есть. Ошибка внутри метода
сцены не роняет приложение: она уходит в журнал.

### Жёсткие правила

1. **`pause()` останавливает всё.** Неактивная сцена — 0 rAF и 0 таймеров. Это
   проверяется на приёмке. Схема из демо:

   ```js
   function start() { if (raf) return; raf = requestAnimationFrame(loop); }
   function stop()  { if (!raf) return; cancelAnimationFrame(raf); raf = 0; }
   ```

2. **Верстайтесь от зон хрома.** Ядро объявляет, сколько места заняли навигация,
   переключатель языков и шестерёнка — по всем четырём сторонам:

   ```css
   .my-scene {
     position: absolute; inset: 0;
     padding: var(--chrome-top) var(--chrome-right)
              var(--chrome-bottom) var(--chrome-left);
   }
   ```

   Хардкодить отступы под хром нельзя: оператор двигает его из настроек, в режиме
   слабовидящих таргеты растут на четверть, а в раскладке «стрелки по бокам»
   занятой оказывается ширина, а не высота.

   Зоны считаются от настроек **и** дополнительно замеряются по факту, берётся
   большее: кнопки языков в a11y или на узком экране переносятся в две строки, и
   расчёт по конфигу их недооценил бы — шапка сцены уехала бы под них.
   `--kiosk-safe-*` — прежние имена тех же переменных, продолжают работать.

   **Зоны могут оказаться УЖАТЫМИ.** Хром считается от размера кнопок и
   масштаба, экран в этот счёт не входит: на невысоком окне сумма зон
   перерастает высоту (1440×900 при `nav.size` 160 и `scale.ui` 1.5 в a11y —
   918 при 900). Тогда кит ужимает зоны пропорционально, оставляя полю сцены
   четверть экрана, и предупреждает в консоли. Это осознанно худший экран —
   ваш край уходит под бар, — но деградация вместо развала: без ужатия поле
   выходило отрицательным и вёрстка схлопывалась целиком. Лечится настройками,
   а не вёрсткой; `KioskSettingsAudit` называет такие сочетания провалом, даже
   когда геометрия уже спасена.

3. **Размеры — только из переменных кита**, и правильно разложенные по двум
   масштабам (см. ниже «Масштаб интерфейса и контента»):

   - **контролы** (кнопки, чипы, легенды, подписи фильтров) — от `--touch-min`,
     `--touch-primary`, `--touch-gap`, `--type-min-label`, `--type-min-ui`;
     они уже завязаны на `--ui-scale`;
   - **контент** (карточки, тексты, подписи на картах, размер точек) — свой кегль
     через `calc(38px * var(--content-scale))`.

   **Числа в `calc()` задавайте сразу под 3840**, а не под ноутбук: у МТК 40
   `calc(16px * var(--content-scale))` дало на панели ровно 16 px — вдвое меньше
   канонных 24. `--content-scale` — это ручка ОПЕРАТОРА поверх готового размера,
   а не множитель, которым вёрстка добирает нехватку. Нижнюю границу держите
   явно:

   ```css
   font-size: max(var(--type-min-label), calc(28px * var(--content-scale)));
   ```

   Тогда оба регулятора и режим слабовидящих сработают сами. Прежнее имя
   `--a11y-scale` осталось и равно `--content-scale` — ломать ничего не нужно.

   **Мерить DOM сразу после смены токенов нельзя.** Ядро гарантирует, что новые
   значения `--ui-scale` / `--content-scale` выставлены **до** вызова
   `setA11y()`, но Chromium материализует перелайаут поддеревьев с
   `content-visibility` только следующим кадром: синхронный
   `getBoundingClientRect()` вернёт старые числа. Макрозадача (`setTimeout`)
   тоже не спасает — воспроизведено у МТК 42.

   ```js
   setA11y(on) {
     this.el.classList.toggle("is-a11y", on);
     requestAnimationFrame(() => this.relayout());   // либо RO на самом элементе
   }
   ```

   **Мерить после смены сцены — только с погашенными переходами.**
   `showScene()` возвращает промис, который резолвится ПОСЛЕ кроссфейда, так что
   `await` обязателен и его достаточно для самого кита. Но ваши собственные
   анимации кит не ждёт, а переход слоя гасится ровно к концу `fade` — замер в
   тот же тик может застать последний кадр. Для замеров глушите переходы и
   анимации целиком, а не у одного меряемого элемента (у МТК 40 из-за этого
   вышло −182 px вместо +40):

   ```js
   const kill = document.createElement("style");
   kill.textContent = "*,*::before,*::after{transition:none!important;animation:none!important}";
   document.head.appendChild(kill);
   // …замеры…
   kill.remove();
   ```

   `transition-duration: 1ms` вместо `none` не годится: в безкадровой вкладке
   переход не доигрывает вовсе и застывает на первом значении.

4. **Скроллы видимые.** Каждому скроллируемому контейнеру — `class="kiosk-scroll"`.

   **Подсказку жеста вешайте на контейнер сцены, а не на `<canvas>`.** Браузер не
   рисует детей холста — его содержимое это запасной контент для тех, кто тег не
   поддерживает, и подсказка внутри невидима с рождения. Так она и жила у пяти
   сцен МТК 38 и на карте 42, пока не вскрылось ревью. Кит теперь сам
   перевешивается на родителя и предупреждает в консоли, но правильный вызов —
   сразу с контейнером:

   ```js
   KioskHint.attach(this._root, { gesture: "pinch" });   // не this._canvas
   ```

   Жесты: `pinch`, `drag`, `tap`, `swipe`. Незнакомый жест даёт `pinch` и
   предупреждение — молча подменять больше не будет.

   **Подъём над своими контролами — через `--kiosk-hint-lift`**, а не через
   `bottom`. Кит сам считает, сколько нужно, чтобы обойти хром ядра
   (`--kiosk-hint-base`, пересчитывается при изменении контейнера и окна), но про
   ваш нижний плеер или ряд чипов он не знает:

   ```css
   .my-scene .kiosk-hint { --kiosk-hint-lift: calc(var(--touch-primary) + 40px); }
   ```

   Переопределять `bottom` целиком не нужно: так вы заново считаете зону хрома,
   которая меняется от настроек и режима. Переход с прежних правил — см.
   [MIGRATION-1.11.md](MIGRATION-1.11.md).

   **Гасить надолго — `suppress()`, а не `hide()`.** У них разные задачи, и
   путать их дорого:

   ```js
   hint.hide();       // на время взаимодействия — ВЕРНЁТСЯ через idleMs
   hint.suppress();   // убрать и держать — переживает любые poke/hide
   hint.resume();     // снять подавление, цикл простоя пойдёт заново
   ```

   `hide()` перевзводит цикл намеренно: сцена гасит призыв на время жеста, и он
   обязан вернуться. Поэтому гашение одним `hide()` на входе в заставку не
   работает — подсказка загорается через полминуты **поверх аттрактора** и горит
   до утра (замер МТК 41: t = 105 c, `is-on`, поверх бокса заставки; вуаль
   полупрозрачна и не прячет).

   **Но для заставки звать ничего не нужно** — ядро гасит подсказки само на
   входе и снимает на выходе (`KioskHint.suppressAll`), раньше, чем сцена
   получит управление. Так что паттерн «показать призыв руками на выходе из
   заставки» продолжает работать. `suppress()` — для СВОИХ причин сцены.

   **Подсказка живёт только у АКТИВНОЙ сцены.** Ушли со сцены — ядро гасит её
   призыв и не даёт циклу догорать в фоне; вернулись — цикл начинается заново.
   Без этого `keepAlive`-сцена выходила на экран с уже горящей подсказкой:
   касание бара навигации видит ядро, а слушатель на контейнере сцены — нет.
   Гасить призыв в `resume()` вручную больше не нужно.

   Перевзводится именно ЦИКЛ ПРОСТОЯ, а не первый показ: иначе листание
   стрелками давало бы вспышку призыва через 1.2 с на каждом переключении.
   Ваш собственный `suppress()` переключение сцен переживает — это отдельное
   состояние, и снимает его только ваш `resume()`.

   **У подсказки ДВА таймера, и `poke()`/`hide()` трогают только один.** Кроме
   цикла простоя есть одноразовый первый показ (`firstDelay`, 1.2 с — чтобы не
   мигать во время загрузки), и «отметить взаимодействие» его не отменяет: это
   не отмена показа, а перевзвод цикла. Отменяет оба только `suppress()` — и
   `suppressAll()` ядра. Поэтому сцена, смонтированная **во время заставки**
   (ленивый `mount` при ротации), не вспыхнет через 1.2 с: подсказка,
   созданная под активным подавлением, рождается подавленной и первый показ не
   взводит вовсе. Проверять `app.idleState` перед `attach()` не нужно.

   **`hint.js` — отдельный скрипт со своей меткой кеша**, и проверка версий его
   не покрывает: она сверяет `kiosk-core.js`. Поднимайте `?v=` на нём вместе с
   ядром, тем же числом:

   ```html
   <script src="../assets/shared/kiosk/hint.js?v=1.21.2"></script>
   ```

   Иначе браузер отдаст подсказку прошлого релиза, а вы будете смотреть на
   поведение, которого в ките уже нет.

   **И не на прокручиваемый контейнер.** Внутри скроллера `absolute`
   отсчитывается от высоты содержимого, а не от видимой области: у маятника
   МТК 42 подсказка встала на `y = −188`, за верхней кромкой. Кит поднимается до
   ближайшего непрокручиваемого предка и предупреждает, но передавайте обёртку
   сразу.

   **Один ФИНАЛЬНЫЙ хост — один владелец подсказки.** Владение считается не по
   тому элементу, который вы передали, а по тому, куда кит в итоге поднялся.
   Два **разных** контейнера могут сойтись в один хост — например, оба лежат
   внутри одного скроллера, и подъём выводит обоих к его родителю. Тогда второй
   `attach` вернёт тот же handle: жест и подпись первого будут перезаписаны (кит
   об этом предупредит), а `destroy()` одного снимет подсказку у обоих.

   Нужны две независимые подсказки — дайте им **разные непрокручиваемые
   обёртки**, а не просто разные контейнеры.

   И ещё: кит ставит финальному хосту `position: relative`, если тот статичен.
   Это меняет систему координат для чужих `absolute`-потомков внутри него —
   если в вашей обёртке такие есть, позиционируйте их явно.

   **Показ возвращается сам.** `hide()` перевзводит цикл: подсказка появится
   снова через `idleMs`. Если взаимодействие до контейнера не дошло (жест
   перехвачен, касание съел оверлей) — отметьте его вручную: `hint.poke()`.
   И держите `timings.standby` заметно больше `idleMs` подсказки, иначе она не
   успевает показаться до заставки.

5. **Строки — через словари.** `ctx.app.t("cards.state", { shown, total })`, а не
   хардкод в разметке. Непереведённый ключ показывается как ключ — так его видно
   на приёмке.

6. **Буфер ≤ 8.3 Мп.** На 4K с DPR 2 наивный `canvas.width = clientWidth * dpr`
   вылезает за бюджет — ограничивайте (пример: `demo/scenes/canvas-scene.js`).

7. **Ноль сети.** Только вендоренные библиотеки, никаких CDN. Проверка —
   `tools/audit-offline.py`.

### Свой аттрактор в простое

По умолчанию в standby все сцены встают на паузу и ядро рисует общую заставку.
Если у МТК есть свой материал для заставки — верните из `standby()` **штатный
тикер ядра**, и ядро оставит только призыв «Коснитесь экрана»:

```js
standby() {
  return this.app.standbyTicker((t) => this.drawSlow(t));   // t — секунды простоя
}
```

`standbyTicker` держит `timings.standbyFps` из конфига и сам останавливается
при касании. Не пишите свою петлю на `requestAnimationFrame`: она будит
композитор каждый vsync, а заставка висит часами — это GPU и выгорание панели.
Дефолт — 10 кадров в секунду, потолок задаёт схема настройки (сейчас 15) и
одинаково действует и на значение из панели, и на значение из `kiosk.config.json`.

### Самопроверка сцены

Необязательный `healthcheck()` ловит то, чего структурные проверки не видят, —
«загружено, но пусто»: DOM на месте, сеть чиста, а на экране ничего.

```js
healthcheck() {
  if (!this.canvas) return { ok: true, detail: "не смонтирована" };   // КАНОН, см. ниже

  // Мало «сколько сущностей»: считайте и РАЗРЕШЕНИЕ буфера.
  const box = this.canvas.getBoundingClientRect();
  const need = box.width * box.height * 0.9;
  if (this.canvas.width * this.canvas.height < need) {
    return { ok: false, detail: `буфер ${this.canvas.width}×${this.canvas.height} при боксе ${Math.round(box.width)}×${Math.round(box.height)}` };
  }
  if (!this.points.length) return { ok: false, detail: "ни одной точки на карте" };
  return { ok: true, detail: "точек " + this.points.length };
}
```

Три канона, все из находок тиража:

1. **Несмонтированная сцена возвращает `{ ok: true, detail: "не смонтирована" }`.**
   Стенд зовёт `healthcheck()` у всех включённых сцен, а смонтирована в этот
   момент только активная (`keepAlive` монтирует по первому показу). Если
   отвечать `ok: false`, приёмка краснеет по всем сценам кроме одной, и настоящая
   авария теряется в шуме. «Не смонтирована» — не поломка, а «нечего проверять».

   **То же и для смонтированной, но ни разу не показанной канвовой сцены**
   (заявка МТК 41). Бокс неактивного слоя **может быть и нулевым, и полным** —
   это зависит от того, как слой спрятан: текущее ядро прячет его
   `visibility: hidden` и `content-visibility: hidden`, и бокс остаётся
   полноразмерным (1920×1080 на киоске, замерено на 1.20.3); при другом способе
   сокрытия он был бы нулевым. Именно поэтому мерить надо ЖИВЬЁМ, а не хранить
   однажды снятое. Ноль означает «ещё нечего мерить», а не поломку:
   `{ ok: false, detail: "буфер 0×0" }` был бы честным по букве и ложным по
   смыслу. Отвечайте `{ ok: true, detail: "ещё не показывалась" }`:

   ```js
   healthcheck() {
     if (!this.canvas) return { ok: true, detail: "не смонтирована" };
     const box = this.canvas.getBoundingClientRect();
     if (!box.width || !box.height) return { ok: true, detail: "ещё не показывалась" };
     // …дальше настоящие проверки: разрешение буфера, число сущностей
   }
   ```

   Отличать этот случай от аварии надо ПО РАЗМЕРУ БОКСА, а не по флагу «меня
   уже показывали»: флаг придётся сбрасывать руками, и он разойдётся с
   действительностью. И помните смежное правило из `GRABLI.md`: геометрия, от
   которой зависит `healthcheck`, пересчитывается **вне кадра** — мерить сразу
   после смены токенов или показа сцены нельзя, вернутся прежние числа.
2. **Проверяйте разрешение буфера, а не только счётчик сущностей.** У МТК 42
   счётчик точек был зелёным, пока карта рисовала в 4 % разрешения — холст
   остался `300×150` при боксе в 4K. Порог: буфер не ниже 90 % площади бокса.

Если ни одна сцена не объявила `healthcheck` — проверка помечается пропущенной,
а не пройденной.

## Подводные камни

Собрано по фактам с пилота МТК 42 — на это натыкаются все, и вслепую отладить
трудно.

### `loading="lazy"` внутри слоя сцены не срабатывает никогда

Слой монтируется прозрачным (`opacity: 0`) — браузер не считает такие картинки
видимыми и откладывает загрузку навсегда. У пилота 128 портретов так и остались
`complete: false`, картинки не появлялись до ручного скролла.

```html
<!-- НЕ работает внутри .kiosk-layer -->
<img loading="lazy" src="…">
<!-- Правильно: обычная загрузка, а тяжёлое — в преролл ядра -->
<img src="…">
```

Тяжёлые наборы отдавайте ядру: `preload: { images: [...] }`. Оно загрузит их на
сплэше с прогрессом, положит в `ctx.images[url]`, и в рантайме сети уже не будет —
чего киоск и требует. Ленивая загрузка тут не оптимизация, а способ показать
посетителю пустые рамки.

### ResizeObserver стреляет нулевой шириной

Скрытый слой имеет размер 0×0. При каждом показе сцены ResizeObserver даёт сначала
`0`, потом настоящую ширину — и сцена, пересобирающая всё по этому событию, дважды
перестраивается на каждом переключении (а на нуле ещё и делит на ноль).

```js
this._ro = new ResizeObserver(() => this.applySize());

applySize() {
  const w = el.clientWidth, h = el.clientHeight;
  if (!w || !h) return;               // ноль — это «слой спрятан», а не новый размер
  if (w === this._w && h === this._h) return;
  this._w = w; this._h = h;
  this.relayout();
}
```

И не полагайтесь на ResizeObserver как на источник ПЕРВОЙ раскладки: в скрытой
вкладке он тоже не доставляется. Меряйте размер сами в `mount()` и `resume()`, а
наблюдателя оставьте для последующих изменений.

### Ожидания в скрытой вкладке

Пока вкладка в фоне, браузер не вызывает `requestAnimationFrame` вовсе и душит
`setTimeout`/`setInterval` до одного раза в минуту. Ядро это переживает само
(переходы завершаются мгновенно, ватчдог в фоне молчит), но **ваши** ожидания —
нет. Для собственных анимаций берите утилиты ядра, а не голый таймер:

```js
const { waitFade, nextFrames, isHidden } = KioskCore.util;
await waitFade(400);     // завершится сразу, если вкладка ушла в фон
```

На самом киоске (Chrome --kiosk во весь экран) вкладка всегда видима — это про
разработку и про демо-стенд, но зависшее в фоне приложение вы будете отлаживать
именно у себя.

### `?v=N` не пробивает кеш импортированных модулей

`<script src="./app.js?v=1.21.2">` обновит только сам `app.js`. Его
`import "./scenes/map.js"` уходит без версии — и браузер отдаст старую копию
сцены. Правка сцены «не доезжает», хотя версию вы подняли.

**У ядра это уже решено:** `kiosk-core.esm.js` тянет версию из собственного
адреса, так что `import … from "…/kiosk-core.esm.js?v=1.21.2"` загрузит и
`kiosk-core.js?v=1.21.2`. Версия ядра поднимается в одном месте. **У ваших сцен —
нет:** тут думать вам.

### Канон версий кита

**Всё из `assets/shared/kiosk/` версионируется ТОЧНОЙ версией ядра**, а не
собственной нумерацией приложения, и поднимается при каждом `merge main`:

```html
<link rel="stylesheet" href="../assets/shared/kiosk/kiosk.css?v=1.21.2" />
<link rel="stylesheet" href="../assets/shared/kiosk/kiosk-core.css?v=1.21.2" />
<script type="module" src="./app.js?v=1.21.2"></script>
```

```js
import { createApp } from "../assets/shared/kiosk/kiosk-core.esm.js?v=1.21.2";
import { mapScene }  from "./scenes/map.js?v=1.21.2";   // импорты сцен тоже!
```

За один день на залипший кеш кита независимо наступили МТК 38, 40 и 42 — своя
нумерация не помогает, потому что по ней не видно, какое ядро на самом деле
поднялось. Поэтому сверка версий встроена.

Сверяет **обёртка** `kiosk-core.esm.js`, а не само ядро, и это принципиально.
Главный случай — свежая метка и старое тело: проверка внутри ядра его не поймает,
у старых версий её просто нет. Обёртка же всегда свежая — её адрес и несёт
бампнутую метку. **Журнал пишет тоже обёртка**, напрямую в
`localStorage["<appId>-kiosk-log"]`: если бы запись делало ядро, эта половина
проверки была бы мертва ровно для тех версий, ради которых затевалась.

Реакция зависит от того, что именно разошлось:

| Метка `?v=` | Что это значит | Реакция |
|---|---|---|
| новее версии ядра (`1.9.2` → работает `1.8.2`) | браузер отдал файл из кеша | предупреждение **и запись в журнал** |
| старее (`1.7.0` → работает `1.9.2`) | файл свежий, метку не подняли после merge | совет в консоль, журнал не трогаем |
| не в формате версии (`182`, `2`) | нарушение канона, но не признак кеша | совет в консоль, журнал не трогаем |
| метки нет вовсе | сверять не с чем — залипание пройдёт молча | совет в консоль, журнал не трогаем |

Различие не косметическое: в `main` три приложения из четырёх помечены не версией
ядра, и жёсткая сверка копила бы им ложные записи в журнал приёмки на каждом
старте — ровно тот «красный, которому перестают верить».

⚠️ **Classic-путь (`<script src="kiosk-core.js?v=…">`) так закрыть нельзя**: там
сверять некому, кроме самого залипшего файла. Со старым ядром рассинхрон пройдёт
молча. Если подключаетесь классическим скриптом — версию проверяйте глазами
(`KioskCore.version` в консоли) либо переходите на ESM-обёртку.

`kiosk.config.json` ядро грузит с `no-cache` — правка таймингов доезжает и без
метки. Для словарей есть `i18nVersion`.

Адрес словарей `i18n/<lang>.json` строит ядро, и версию туда передать было
нечем — Chrome держал старый словарь после обновления сборки, новые ключи не
доезжали (нашли у МТК 38). Для этого есть опция `i18nVersion`: поднимайте её
вместе с `?v=` остальных файлов.

Пока правите — проверяйте с DevTools → Network → Disable cache. При выкладке на
киоск проще всего гарантировать свежесть, перезапустив Chrome с чистым профилем
или подняв версию у всей папки (перенос в `app-v5/`). Разово подтянуть один модуль
из консоли: `await import("./scenes/map.js?fresh=" + Date.now())`.

### Долгая операция и ватчдог

Если сцена честно держит поток дольше `watchdog.stallSec` (генерация текстур,
тяжёлый разбор данных) — предупредите ядро, иначе оно сочтёт это зависанием:

```js
app.suspendWatchdog();
try { await heavyThing(); } finally { app.resumeWatchdog(); }
```

## Масштаб интерфейса и контента

Два **независимых** регулятора, оба в сервис-панели (группа «Масштаб»):

| Настройка | Переменная | Что тянет |
|---|---|---|
| «Интерфейс киоска» | `--ui-scale` | кнопки навигации, чипы, переключатель языков, тач-таргеты, подписи контролов, ширина скролла |
| «Контент сцен» | `--content-scale` (`--a11y-scale` — прежнее имя того же) | всё, что сцена рисует сама: карточки, тексты, подписи на картах, размер точек |

Одного общего множителя не хватает: крупный интерфейс съедает место у контента,
крупный контент — у кнопок, и что-то одно всегда оказывается плохо видно. Поэтому
регуляторы разделены, а не связаны.

Отступы от кромки (`--edge-safe`, `--edge-safe-bottom`) **не масштабируются**:
это физика панели — рамка и ладонь, а не размер шрифта.

**Режим слабовидящих домножает оба**, не заменяя их: `a11y.uiBoost` (деф. ×1.25)
и `a11y.contentBoost` (деф. ×1.5, канон Киоск-стандарта). Настройка оператора при
этом сохраняется: контент ×1.75 + режим = ×2.625. Размеры в режиме больше не
задаются фиксированными пикселями — иначе они затирали бы то, что выставил
оператор, и два регулятора конфликтовали бы.

Класс `.a11y` на `<html>` теперь несёт **только контраст-тему** (цвета), не размеры.

## Поле контента

Отдельно от масштабов — сами габариты содержимого. **Приложение всегда во весь
экран**; поджимается не оно, а поле контента внутри сцены: на панели 2160 px
шириной строка во всю ширину нечитаема, и кеглем это не лечится.

Два регулятора в группе «Поле контента» (`content.width` / `content.height`, %)
дают сцене переменные `--kiosk-content-w` / `--kiosk-content-h` и готовый
контейнер — класс `.kiosk-content`: ширина, **потолок** по высоте и центрирование
по обеим осям. Высота именно потолком (`max-height`), а не жёстким размером:
поле почти всегда лежит во flex-колонке сцены, где `flex-basis` перебил бы
`height` — и регулятор высоты просто не работал бы.

Проценты считаются от того контейнера, **в который вы его положили**, поэтому
кладите внутрь своей области с отступами:

```html
<div class="my-scene">            <!-- padding: var(--kiosk-safe-*) -->
  <div class="my-scene__chrome">…</div>     <!-- фильтры во всю ширину -->
  <div class="my-scene__body kiosk-content">…</div>   <!-- контент поджат -->
</div>
```

Пока открыта сервис-панель, граница поля подсвечена пунктиром — иначе «Ширину
поля» приходится крутить вслепую.

## Запомнить настройки

Правки оператора сохраняются **сразу** — в `localStorage`. Но он умирает вместе с
профилем браузера: переустановка киоска, чистка кеша, новый компьютер — и всё
выкручено заново. Поэтому в панели есть перенос:

- **«Выгрузить в файл»** — скачивает готовый `kiosk.config.json` с текущими
  значениями. Отдайте его сессии МТК: она кладёт файл в git, и настройки
  переживают что угодно. Это и есть постоянное место настройки.
- **«Загрузить из файла»** — восстанавливает снимок (ложится поверх файла целиком
  и перезапускает приложение).
- **«Сбросить настройки»** в подвале — удалить правки и вернуться к тому, что
  лежит в `kiosk.config.json`.

## Навигация: две раскладки

- `nav.layout: "bar"` — стрелки в баре по бокам от заголовка (по умолчанию).
- `nav.layout: "sides"` — стрелки у левого и правого края экрана, как в прежнем
  хабе; в баре остаются только заголовок и точки. Положение задаётся точно, как
  было в хабе (он отмирает — настройка не должна пропасть вместе с ним):
  `nav.sideY` — вертикаль 5–95 % высоты, `nav.sideX` — отступ от кромки 0–200 px.
  На вертикальной панели 2160×3840 середина бывает слишком высоко для посетителя.

Переключается из сервис-панели («Навигация» → «Стрелки»). Полосы
`--kiosk-safe-*` пересчитываются сами: в «sides» занят край по горизонтали,
а нижняя полоса становится ниже.

## Журнал и версии

Записи помечаются версией ядра и меткой запуска (`sid`). При **обновлении ядра**
журнал очищается — но сам факт записывается строкой «журнал очищен при
обновлении…», чтобы не потерять след аварии перед апдейтом. Записи прошлых
запусков той же версии сохраняются, но в панели приглушены и подписаны меткой,
а счётчик аварий показывает отдельно «за этот запуск» и «всего».

Без этого после обновления на приёмке видны чужие аварии, а самая верхняя строка
«версия ядра …» оказывается самой старой — и кажется, что ядро не обновилось.

Какая версия работает прямо сейчас: строка в консоли при старте
(`[kiosk] ядро 1.2.0 · mtk42 · запуск A1B2C3`) и подпись в подвале сервис-панели.

## Состав и порядок экранов

Группа **«Экраны»** в сервис-панели — оперативная настройка киоска: оператор
гасит незаконченный экран или меняет порядок листания, не трогая код. Сессиям
МТК делать ничего не нужно, реестра сцен достаточно.

- Тумблер вкл/выкл и кнопки вверх/вниз на каждый экран. Последний включённый
  выключить нельзя — пустой киоск невозможен.
- Порядок листания (стрелки, точки) и «Стартовый экран» следуют этому списку;
  в стартовые предлагаются только включённые.
- Выключенный экран **не участвует в прероле** — прямая экономия времени
  запуска. Его точка скрыта, а `showScene("<id>")` и диплинк `#<id>` уводят на
  стартовый: ссылка на погашенный экран не должна давать пустоту.
- Включённый обратно в рантайме экран догружает свои ассеты сам — иначе
  оператор увидел бы пустой контент вместо картинок.
- Хранение: `screens.order` (массив id) и `screens.enabled` (id → false) в
  `kiosk.config.json`, localStorage поверх, «Сбросить» возвращает конфиг,
  выгрузка файлом подхватывает. Порядок из конфига может отстать от кода —
  недостающие сцены дописываются в порядке регистрации, лишние игнорируются.
- Ключ **отдельный** от `scenes[<id>]` с настройками сцен: в общем объекте
  сцена с id `order` затёрла бы состав. С 1.6.0 состав лежал в
  `scenes.order/enabled` — ядро переносит его в `screens` при старте
  автоматически, в том числе из localStorage оператора.

## Настройки сцены (главное для сессий МТК)

Сцена **объявляет** свои параметры — ядро само рисует их в сервис-панели, хранит и
возвращает обратно. Так тюнинг-панели прототипов переезжают в одно место, одинаково
у всех пяти МТК.

```js
export const mapScene = {
  id: "map",
  title: { ru: "Карта" },

  settings: [
    { key: "dotSize", label: { ru: "Размер точек", en: "Dot size" },
      type: "range", min: 6, max: 24, step: 1, unit: " px", default: 12 },
    { key: "labels", label: { ru: "Подписи городов" },
      type: "toggle", default: true },
    { key: "projection", label: { ru: "Проекция" }, type: "select", default: "winkel",
      options: [["winkel", "Винкель"], ["equirect", "Прямоугольная"]] },
  ],

  applySettings(values) {          // на старте и при каждом изменении
    this.dotSize = values.dotSize;
    this.redraw();                 // без перезагрузки страницы
  },
};
```

- Типы: `range` (min/max/step/unit), `toggle`, `select` (`options`).
- `label` — строка или `{ru, en?, zh?}`.
- Хранение: `localStorage["<appId>-kiosk"].scenes[<id>]` **поверх дефолтов схемы**, и
  только реально изменённые ключи. Дефолт, записанный в патч, затенил бы будущую
  правку схемы навсегда — поэтому «Сбросить сцену» ключи *удаляет*, а не переписывает.
- В панели каждая сцена получает свою **сворачиваемую** группу «Настройки МТК · <сцена>»
  со счётчиком параметров и кнопкой «Сбросить сцену». По описи у МТК 38 их около
  шестидесяти — развёрнутыми они превратили бы панель в ленту, где ничего не найти.
- `applySettings` вызывается сразу после `mount()` и при каждом изменении.

## Настройки уровня приложения

Когда эффект принадлежит не сцене, а приложению — объявляйте его в `createApp`,
не в сцене:

```js
const app = createApp({
  appId: "mtk42",
  appSettings: [
    { key: "photoColor", label: { ru: "Цвет фотографий" }, type: "select",
      default: "mono", options: [["mono", "Монохром"], ["color", "Цвет"]] },
  ],
});
```

```js
// в КАЖДОЙ сцене, которой это касается:
applyAppSettings(values) { this.setPhotoMode(values.photoColor); }
```

Ядро зовёт `applyAppSettings` у **всех смонтированных сцен** — в этом и смысл.
Группа в панели называется «Настройки МТК · общие», хранение — `app.<key>`,
сброс отдельной кнопкой.

Почему не через сцену: у МТК 42 цвет портретов делят картотека и маятник.
Объявить в одной — оператор меняет «цвет фото» в группе «Картотека», а меняется и
маятник: подпись врёт. Объявить в обеих — два независимых значения на один
эффект. Ровно из-за этого пробела `addSettings()` и нельзя было объявить
устаревшим по-настоящему.

Императивный `app.addSettings(группа, строки)` **устарел**: для настроек сцены
есть `settings:[]`, для общих — `appSettings:[]`. Он продолжает работать и один
раз предупреждает в консоли.

## Сервис-панель

Вход: `?service=1`, шестерёнка или тройной тап. Пока панель открыта, простой
заморожен.

**`service.gear`** — три режима, переключаются из самой панели (группа
«Сервис-панель»):

| Режим | Шестерёнка | Тройной тап | Кому |
|---|---|---|---|
| `always` (деф.) | видна | по заголовку | обычный тач-киоск |
| `tripleTap` | скрыта | по заголовку **и** по её углу | витрина без видимых служебных элементов |
| `hidden` | скрыта | нет | панель без тача: вход только `openService(true)` из кода |

Тройной тап в режиме `tripleTap` ловится и по заголовку навигации, и по углу,
где была бы шестерёнка (справа вверху, `--edge-safe` + `--touch-primary`).
Второй вход не для удобства: заголовка может не быть вовсе — навигация скрыта
или `nav.showTitle: false`, — и тогда режим запирал бы сервис намертво.

Режим `hidden` действительно не оставляет входа с экрана, поэтому при выборе из
панели ядро переспрашивает: настройка живёт в `localStorage` и переживает
перезагрузку. Берите его, только если у приложения есть свой вход
(`app.openService(true)` по комбо физических кнопок).

Своя группа настроек — тем же видом контролов, что у ядра:

```js
app.addSettings("Карта", [
  { type: "range",  path: "map.dotSize", label: "Размер точек", min: 48, max: 160, step: 8, unit: " px" },
  { type: "toggle", path: "map.showLabels", label: "Подписи стран" },
  { type: "choice", path: "map.projection", label: "Проекция",
    options: [["winkel", "Винкель"], ["equirect", "Прямоугольная"]] },
]);

app.on("setting", ({ path, value }) => { /* применить у себя */ });
```

Типы строк: `range`, `toggle`, `choice`, `text`, `scene` (список ваших сцен).

## Финдер: поиск, отбор, сортировка

Канон — [PLAN-KIOSK.md](../../../PLAN-KIOSK.md) → «Финдер». Сцена **объявляет**,
чем можно искать; применяет — **одним методом**:

```js
export const mapScene = {
  finder: {
    search:  { fields: [{ key: "title", label: { ru: "Название", en: "Title" } }] },
    filters: [{ key: "kind", label: { ru: "Вид", en: "Kind" },
                options: () => KINDS.map((k) => [k, k]) }],   // массив ИЛИ функция
    sorts:   [{ key: "az", label: { ru: "По алфавиту", en: "A→Z" } }],
  },

  applyFinder({ query, filters, sort }) {
    // ЦЕЛИКОМ, при любом изменении. Порядок: отбор → поиск → сортировка.
    this._find = { query, filters, sort };
    this.redraw();
    return { shown: this.visible.length, total: this.all.length };   // необязательно
  },
};
```

**Состояние держит ядро, и держит по сценам.** Отбор живёт до idle-сброса и не
гаснет при уходе со сцены — вернувшийся посетитель видит свой отбор, а точка на
иконке показывает отбор ТЕКУЩЕЙ сцены. Из этого же следует: после `mount()` ядро
зовёт `applyFinder` заново, поэтому сцена с `keepAlive: false` не обязана ничего
помнить — иначе она вернулась бы с полным списком при горящей точке.

`options` можно задать функцией: фасеты обычно выводятся из загруженных данных, а
декларация читается, когда данных ещё нет.

**Что делает ядро само:** рисует лупу (только сценам с `finder`), считает точку —
число активных **критериев**, открывает панель, ведёт экранную клавиатуру RU/EN,
гасит отбор на idle-сбросе **до** вашего `reset()`, закрывает панель тапом мимо.
Пер-пунктовые `apply()` остаются сахаром; канон — `applyFinder`.

**«N из M»** появится в подвале панели, если `applyFinder` вернул `{shown,total}`.
Не вернул — строки не будет, обязанности считать у сцены нет.

### Поиск может не построиться — и это не поломка

Экранной клавиатуре нужно место. Если его нет даже на один ряд букв, кит
**не строит строку поиска вовсе**: панель живёт чипами и сортировкой, а мёртвого
поля, которое обещает ввод и не даёт его, не остаётся. Отказ громкий —
`console.warn`, запись в журнал с числами и провал в `KioskSettingsAudit`.

Порог считается **замером вмещаемости**, а не порогом по масштабу, но на
практике сводится к одному числу — **действующему `--ui-scale`**:

| действующий `--ui-scale` | поиск |
|---|---|
| до 1.25 включительно | строится |
| 1.5 | **не строится** |

Важно, что действующий масштаб — это **произведение**: режим слабовидящих
умножает операторский `scale.ui` на 1.25. Поэтому

- `scale.ui` 1 + a11y = 1.25 → поиск есть;
- `scale.ui` 1.2 + a11y = 1.5 → **поиска нет**.

Формулировка «в режиме слабовидящих всё в порядке» неверна: она верна только
при `scale.ui` = 1. Числа на 1920×1080 при `nav bar/bottom/96`: 1.25 даёт
159 px под клавиатуру при нужных 80, 1.5 — 12 px при нужных 96.

**Вмещаемость измерима только на ОТКРЫТОЙ панели.** `app.finderSearchFits()`
на закрытой возвращает `{ fits: null }` — «не мерил», а не «не помещается»:
закрытая панель это другая раскладка, и подгонять одно под другое замером
значило бы завести второе число на одно состояние. Хотите проверить сами —
откройте панель и меряйте:

```js
app.openFinder(true);
const fit = app.finderSearchFits();   // {fits, have, need}
```

Синхронный вызов сразу после `openFinder(true)` уже корректен: ядро показывает
панель ДО отрисовки, и замер идёт по разложенной. Но `fits: null` в ответе —
не повод считать, что места нет: это значит «спросили не вовремя».

Сцене делать ничего не нужно: `finder.search` объявляется всегда, кит сам
решает, строить ли поле. Но если ваша сцена без поиска бессмысленна — скажите
об этом оператору, а не подстраивайте вёрстку.

**Китайский интерфейс.** Пиньинь-IME не делаем: ищут теми же полями (канон данных —
ru/латиница), панель говорит об этом прямо. Строка — `finder.zh` в словаре.

**Пилот — МТК 39**, сопроводиловка с точными адресами: [FINDER-MTK39.md](FINDER-MTK39.md).

**Приёмка.** `tools/sweep.js` разворачивает отбор сам: каждый фильтр и каждая
сортировка становятся состояниями и проверяются через `healthcheck()`. Дублировать
их в `states()` не нужно; следов после прогона не остаётся.

## Проверка перед «готово к merge»

```bash
python3 assets/shared/kiosk/tools/audit-offline.py --path mtk42-app
```

```bash
python3 assets/shared/kiosk/tools/audit-links.py --path mtk42-app
```

Второй проверяет, что каждая локальная ссылка (`href`, `src`, `srcset`, `url()`,
`@import`) ведёт на существующий файл. Битая ссылка не падает и не кричит:
у соседей по МТК 29 опечатка в пути к шрифту увела весь текст в Georgia, и на
глаз это почти неотличимо от задуманного.

Дальше — **два** прогона в приложении, оба обязательны, и они проверяют разное:
стенд приёмки — как приложение живёт в ОДНОМ состоянии настроек, перебор
сочетаний — что оно не разваливается в остальных.

```html
<script src="../assets/shared/kiosk/tools/selftest.js?v=1.21.2"></script>
<script src="../assets/shared/kiosk/tools/audit-settings.js?v=1.21.2"></script>
```

Оба прогона печатают **предусловия рядом с числами** — окно, сцену,
конфигурацию, действующий `--ui-scale` и **список ключей в `localStorage`**.
Тот же блок отдаёт `app.preconditions()`, если снимаете числа своим скриптом:
публикуйте его вместе с результатом.

Список ключей — именно списком, а не галочкой «чисто» (приём МТК 39 из их
опыта): «чисто» глазами пропускается, а строка с чужим ключом заставляет
остановиться. За одну сессию остаток чужих настроек отравил у меня три замера
подряд, и каждый раз это находилось постфактум, при разборе расхождения.

Метка `?v=` нужна и здесь. Инструменты правятся чаще ядра, а грузят их обычно
из консоли на живой странице — без метки браузер отдаёт вчерашнюю копию, и
прогон проверяет не то, что вы только что исправили. Меня это поймало на
собственном ните: правка в `audit-settings.js` была, а прогон её не видел.
```js
KioskSettingsAudit.run(app)      // должно быть «сломано: 0»
```

Второй прогон обязателен с 1.13.0 и введён не для порядка: раскладка «стрелки по
бокам» отдавала полю сцены ОТРИЦАТЕЛЬНУЮ ширину и схлопывала вёрстку любой
сцены — а дожила до прода, потому что и стенд, и оба скептика смотрели только
дефолтные настройки. Оператору достаточно переключить одну строку в панели.
В схлопнутом окне прогон отказывается работать вслух: зелёный результат там
получился бы на любом коде.

Стенд приёмки — подключается тем же способом, в консоли **видимой** вкладки:

```bash
await KioskSelfTest.run(app)
```

Он гоняет 50 циклов по всем сценам и проверяет: рост DOM и JS heap после
прогрева, число слоёв против числа сцен, запросы в сеть после старта, буфер
≤ 8.3 Мп, скрытые полосы прокрутки, размеры тач-таргетов и отступы от кромки.

Прогонять **только в видимой вкладке**: в фоне браузер замораживает кадры, и
проверка «0 rAF» смысла не имеет — стенд честно её пропустит, а не покажет
зелёное. По той же причине в фоне не наступает standby (так и задумано с v1.1).

### Перебор сочетаний настроек

```html
<script src="../assets/shared/kiosk/tools/audit-settings.js"></script>
```
```js
KioskSettingsAudit.run(app)      // 128 сочетаний раскладки, размера и масштаба
```

Стенд приёмки проверяет **одно** состояние настроек — обычно дефолтное. Ломается
же не отдельная ручка, а сочетание: раскладка «стрелки по бокам» отдавала
`--chrome-left/right` по 1872 px при окне 1920, и полю сцены доставалась
отрицательная ширина. На дефолтах это не проявлялось никогда, а оператору
достаточно переключить одну строку в панели.

Проверяются инварианты, не зависящие от содержания сцены: полю остаётся
положительный размер, хром не залезает в это поле, ничего не уехало за край.
В схлопнутом окне прогон **отказывается работать вслух** — зелёный результат там
получился бы на любом коде.

### Перебор состояний

Стенд зовёт `healthcheck()` **один раз**, в том состоянии, в каком застал сцену.
Это ловит «загружено, но пусто», но не ловит обратную ошибку — когда сцена
краснеет на **законном** состоянии экрана. У МТК 39 таких нашлось две, и обе на
сочетании фильтров, которого поодиночке не видно.

```html
<script src="../assets/shared/kiosk/tools/sweep.js"></script>
```

```bash
await KioskSweep.run(app)                # одиночные состояния и пары
```

Состояния берутся из **объявленной схемы настроек** — селекторов разметки тут
нет, ломаться нечему. Диапазоны проверяются по краям и дефолту, тумблеры и
списки — целиком; пары важнее одиночек, потому что ловят именно сочетания.
Настройки восстанавливаются после прогона, таймеры не используются (работает и
в фоновой вкладке), простой и ватчдог глушатся, а пропуск по лимиту называется
вслух — молчаливое усечение читалось бы как «проверено всё».

Перебор **не пишет в настройки оператора**: значения идут через
`setSceneSettingLive()` — в живой конфиг и в сцену, минуя `localStorage`.
Диагностический инструмент не должен оставлять сотни значений в патче, и дело не
только в мусоре: записанный дефолт затенил бы будущую правку схемы.

Посетительские фильтры в схему не входят. Если их нужно перебирать, сцена
объявляет необязательный `states()`:

```js
states() {
  return [
    { name: "все категории", apply: () => this.setFilter("all") },   // ПЕРВОЕ = дефолт
    { name: "астероиды",     apply: () => this.setFilter("asteroids") },
  ];
}

/* Необязательно, но надёжнее договорённости «первое = дефолт»:
   если объявлен — побеждает её. */
restoreState() { this.setFilter("all"); this.scrollTop = 0; }
```

**Состояние обязано возвращаться.** После прогона перебор восстанавливает
посетительские фильтры (`restoreState()`, иначе первое состояние из `states()`) и
возвращает ту сцену, с которой начинали. Без этого посетитель до idle-сброса
видит следы сервиса: у МТК 38 каталог оставался на «pub», карта на «both», а
киоск — на последней сцене списка. Сцены, которым восстановить нечем, попадают в
отчёт красной строкой, а не пропускаются молча.

Что стенд не заменяет и делается руками:

- пройти все сцены туда-обратно глазами: кроссфейд без вспышек и дёрганья;
- DevTools → Network в offline-режиме: после сплэша запросов нет;
- три языка, режим слабовидящих, idle-сброс и standby с укороченными таймингами
  (`localStorage.setItem("mtk42-kiosk", JSON.stringify({timings:{reset:3,standby:6}}))`).

### Тест фоновой вкладки (обязателен)

Ловит целый класс поломок: браузер в фоне замораживает `rAF` и душит таймеры, и
всё, что этого не ждёт, либо виснет, либо ложно срабатывает.

1. Открыть приложение, переключиться на другую вкладку **минимум на 2 минуты**.
2. Вернуться. Проверить:
   - в журнале (сервис-панель) **нет** записей `fatal` и нет следов перезапуска;
   - приложение то же самое, а не перезагруженное;
   - сцены переключаются сразу, без залипания на первом же тапе.

Жёстче и быстрее — не дожидаясь двух минут, загрубив порог до абсурдного:

```js
localStorage.setItem("mtk42-kiosk", JSON.stringify({ watchdog: { stallSec: 2 } }));
location.reload();
// свернуть вкладку на минуту, вернуться, посмотреть журнал: fatal быть не должно
```

Проверено на демо ядра: интервалы в фоне растягиваются до 60 с, при `stallSec: 2`
ни одного `fatal`, переключение сцен в скрытой вкладке — 0–6 мс вместо зависания.

DOM). Оно и образец кода, и стенд для проверки самого ядра. Открывается на общем
сервере (порт 8092, поднимает координатор из main — свой второй не запускать):
`/assets/shared/kiosk/demo/`.

Полезное там: `scenes/canvas-scene.js` —
хелпер с честным rAF-жизненным циклом, ограничением буфера и DPR; `scenes/cards.js` —
DOM-сцена со сбросом состояния и словарями.
