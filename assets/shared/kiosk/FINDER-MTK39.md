# Финдер — пилот МТК 39

Сопроводиловка к внедрению. Механика — в [README](README.md) → «Финдер»; здесь
только то, что относится к вашим семи сценам, и **по вашему коду**, а не по
описанию: адреса вычитаны в `mtk39-app/scenes/*.js`, поля — в
`data/mtk39-corpus.json` (`records`, **1203** записи).

## Коротко: что происходит

Финдер — иконка-лупа в ряду инструментов и панель поверх сцены. Отбор держит
**ядро**, сцена только применяет его одним методом. Ваши чипы никуда не
исчезают сами: переезд — ваша правка, и делать её надо не везде.

## Поля для поиска

В `records` есть `name`, `city`, `country`, `continent`, `kind`, `status`,
`section`, `year_named`, `year_renamed`, `desc`.

Для `search.fields` берите **три**: `name` (название объекта), `city` (город),
`country` (страна). `desc` не берите — там свободный текст с опечатками
источника («Отыркт 29 ноября…»), поиск по нему даст ложные попадания и
объяснить их посетителю будет нечем.

```js
search: {
  fields: [
    { key: "name",    label: { ru: "Название", en: "Name" } },
    { key: "city",    label: { ru: "Город",    en: "City" } },
    { key: "country", label: { ru: "Страна",   en: "Country" } },
  ],
}
```

Подписи обязательны: строка «ищем по…» показывает только те поля, у которых
есть человеческая подпись — ключи посетителю ничего не говорят.

## Что переезжает в финдер, а что остаётся

| Сцена | Что там сейчас | Решение |
|---|---|---|
| `globe.js:530` `buildFilter()` | чипы категорий, 8 крупнейших + «Все» | **в `filters`** |
| `world.js:318` | чипы статуса: все / носит имя / переименован / утрачен | **в `filters`** |
| `world.js:337` | тумблер «без бывшего СССР» | **в `filters`**, как отдельный ключ |
| `world.js:78` | чипы «глобус / карта» | **ОСТАВИТЬ НА МЕСТЕ** |
| `union.js:385` | чипы «что показывать» | **в `filters`** |
| `catalog`, `stats`, `streets`, `wave` | чипов нет | объявить `finder` только там, где поиск осмыслен |

**Про «глобус / карта» отдельно.** Это не отбор, а переключение вида — главное
взаимодействие сцены. В панели оно окажется за два касания вместо одного и
перестанет быть видимым. Канон говорит «чипы сцен со временем переезжают в
финдер», но он про отбор; вид — не отбор. Если решите иначе, скажите, обсудим
до того, как вы это сделаете.

**Про категории `globe`.** Сейчас берутся 8 крупнейших из ~20 — в комментарии у
вас честно написано, почему: «двадцать категорий чипами съедали бы четверть
экрана». В панели этого ограничения нет: она вертикальная и прокручивается.
Отдавайте `options` функцией и **все** категории — это ровно тот случай, ради
которого функция и разрешена.

```js
filters: [{
  key: "category",
  label: { ru: "Категория", en: "Category" },
  options: () => [...new Set(items.map((i) => i.category))]
    .map((c) => [c, CATEGORY_LABELS[c] || c]),
}]
```

## Сортировка

У вас её нет нигде, а корпус её просит: 1203 записи, 74 страны. Предлагаю на
`world` и `catalog`:

```js
sorts: [
  { key: "az",      label: { ru: "По алфавиту",      en: "A→Z" } },
  { key: "country", label: { ru: "По странам",       en: "By country" } },
  { key: "named",   label: { ru: "По году присвоения", en: "By year named" } },
]
```

`year_named` заполнен не у всех — записи без года ставьте в конец, а не в
начало: посетитель, выбравший «по году», ищет годы, а не пустоты.

## Применение

Один метод, целиком, при любом изменении. Порядок канона: **отбор → поиск →
сортировка**.

```js
applyFinder({ query, filters, sort }) {
  this._find = { query, filters, sort };
  this.redraw();                       // ваш обычный перерисовщик
  return { shown: this._visible.length, total: this._all.length };
}
```

Возврат необязателен, но **сделайте его**: у вас 1203 записи, и строка «N из
1203» в панели — единственное, что объясняет посетителю, почему на шаре стало
пусто.

Про `keepAlive` ядро позаботится само: после `mount()` оно зовёт `applyFinder`
заново, так что сцена не обязана помнить отбор через пересборку.

## Замер «до / после» — обязателен

По образцу перехода МТК 40, который дважды окупился. Снимайте **обе половины
одним скриптом на одной сборке**, а не в разные дни.

Для каждой сцены с `finder`, в обоих режимах (обычный и a11y), на трёх языках:

| что мерить | почему |
|---|---|
| число объектов до и после отбора | ловит «фильтр не оставил ничего» |
| `{shown, total}`, который вернул `applyFinder` | должен совпасть с тем, что на экране |
| зазор от панели до навигации и до ваших контролов | панель приходит поверх сцены |
| число строк в подписях чипов | длинные названия стран переносятся |
| `healthcheck()` на каждом критерии | это же делает `sweep.js` — сверьте |

**Мерьте с погашенными переходами** (`transition: none` на всё, не
`1ms` — в безкадровой вкладке он застывает) и **в живой вкладке**: у панели есть
анимация появления, класс вешается в начале, а поза устанавливается в конце.

## Что проверит приёмка

`tools/sweep.js` разворачивает ваш отбор сам: каждый фильтр и каждая сортировка
становятся состояниями и проходят через `healthcheck()`. Дублировать их в
`states()` не нужно. Стенд `selftest.js` прогоняйте **с открытой панелью тоже** —
клавиатура считается хромом, и тач-стандарт на её клавиши проверяется.

## Известное ограничение

Китайский поиск идёт по русским и латинским написаниям — пиньинь-IME не делаем
(решение координатора). Панель говорит об этом сама строкой `finder.zh`; в
китайском словаре она пока русским фолбэком, как и остальные термины до
китаиста.
